# Packaging agent processes for reuse, and the limits on generalising prose-template loops

Research date: 2026-11-03. All Claude Code documentation quotes are from code.claude.com as rendered on that date (pages carry no explicit "last updated" stamp; version gates such as "v2.1.277 or later" are noted where the page gives them). Items marked UNVERIFIED come from search snippets or secondary summaries whose underlying page was not opened.

## Q1. What can a Claude Code hook enforce that a skill or CLAUDE.md cannot (exit codes, blocking, JSON decisions)?

### Takeaway
Anthropic's own docs now draw a hard line: prompts, CLAUDE.md and skills are "non-deterministic (Claude decides)"; hooks, deny rules and managed settings are "deterministic (Claude Code enforces)". A `command`/`http` hook can block a tool call, block a prompt, refuse to let a turn end (Stop), refuse to let a subagent end (SubagentStop), refuse task completion, rewrite tool input, and inject context, all independent of whether the model remembers the rule. Prompt- and agent-type hooks exist but are explicitly "not deterministic either".

### Cited Findings
- Hooks "gives you deterministic control: certain actions always happen rather than relying on the LLM to choose to run them." — [Claude Code hooks guide](https://code.claude.com/docs/en/hooks-guide)
- The best-practices page defines two instruction classes: "1. Non-deterministic: you write the instruction, and Claude (the model) reads it. This can be your prompt, `CLAUDE.md`, or a skill… there's no *guarantee* that it'll follow your instructions. It can still decide not to do things, or do other things. 2. Deterministic: you configure the instruction, and Claude Code (the harness) *has* to execute this. This can be a hook, a deny rule, or a managed setting. Claude Code applies this every time, no matter what the model decided to do." — [Best practices](https://code.claude.com/docs/en/best-practices)
- Same page's table of what each class controls: *what to do* = prompt/CLAUDE.md/skills vs hooks and user-only skills; *what it can touch* = auto-mode classifier vs deny rules, strict sandbox, managed settings; *when it's done* = request for evidence, `/goal`, `/code-review` vs tests, typecheck, a `Stop` hook, CI; *how much it spends* = effort level vs `--max-turns`, `--max-budget-usd`, spend limit. — [Best practices](https://code.claude.com/docs/en/best-practices)
- "If something has to happen every time, make it a hook, a deny rule, or a managed setting. `CLAUDE.md` is for guidelines, and Claude is allowed to decide a guideline doesn't apply." — [Best practices](https://code.claude.com/docs/en/best-practices)
- "If you keep adding emphasis to a `CLAUDE.md` line and Claude still misses it, that's a sign the line belongs in a hook. The reverse holds too: if you have hooks for things that are only preferences, delete them and let Claude decide." … "a hook is for a rule with *zero* exceptions, and `Prefer named exports` has plenty, so that one stays in `CLAUDE.md`." … "keep the enforced set small. Every hook and deny rule will occasionally fire when it shouldn't, and someone has to maintain each one. If you ever find yourself at forty of them, most are probably preferences". — [Best practices](https://code.claude.com/docs/en/best-practices)
- "A line like `Always typecheck before you finish` in this file works most of the time, not every time." The enforced form is a `Stop` hook that exits 2 with compiler output on stderr; "the turn doesn't end until the typecheck passes or the block limit is reached." — [Best practices](https://code.claude.com/docs/en/best-practices)
- Memory page: CLAUDE.md and auto memory are "context, not enforced configuration. To block an action regardless of what Claude decides, use a PreToolUse hook instead. The more specific and concise your instructions, the more consistently Claude follows them." — [Memory](https://code.claude.com/docs/en/memory)
- Hook handler types: `command`, `http`, `mcp_tool`, `prompt`, `agent` (experimental). Default timeouts 600 s for command/http/mcp_tool, 30 s prompt, 60 s agent. — [Hooks reference](https://code.claude.com/docs/en/hooks)
- Events (grouped by the reference): per session `SessionStart`, `SessionEnd`, `Setup`; per turn `UserPromptSubmit`, `UserPromptExpansion`, `Stop`, `StopFailure`; per tool call `PreToolUse`, `PermissionRequest`, `PermissionDenied`, `PostToolUse`, `PostToolUseFailure`, `PostToolBatch`; subagents/tasks `SubagentStart`, `SubagentStop`, `TaskCreated`, `TaskCompleted`, `TeammateIdle`; compaction/models `PreCompact`, `PostCompact`, `PreModelSwitch`, `PostModelSwitch`; MCP `Elicitation`, `ElicitationResult`; other `Notification`, `MessageDisplay`, `InstructionsLoaded`, `ConfigChange`, `CwdChanged`, `DirectoryAdded`, `FileChanged`, `WorktreeCreate`, `WorktreeRemove`. — [Hooks reference](https://code.claude.com/docs/en/hooks)
- Exit codes: exit 0 = success (stdout JSON applied; "Claude never sees stderr from a hook that exits 0"); exit 2 = "blocking error" on blockable events, stderr becomes the reason; any other code = non-blocking, action proceeds. Warning: "Exit code 1 without valid JSON output is a non-blocking error... If your hook is meant to enforce a policy, use `exit 2`." — [Hooks reference](https://code.claude.com/docs/en/hooks)
- Exit-2 effect by event: `PreToolUse` blocks the tool call; `UserPromptSubmit` blocks the prompt; `Stop`/`SubagentStop` "Prevents stopping; continues the conversation"; `TaskCompleted` prevents the task from being marked complete; `PreCompact` blocks compaction; `PostToolUse` only shows stderr to Claude because "the tool already ran"; `PermissionRequest` exit 2 "Not honored; deny via the `decision` object instead"; `Notification`, `InstructionsLoaded` exit code ignored. — [Hooks reference](https://code.claude.com/docs/en/hooks)
- JSON output (exit 0 + one JSON object): universal `continue` (false stops Claude; "takes precedence over any event-specific decision fields"), `stopReason`, `systemMessage`; event-specific top-level `decision: "block"` + `reason` for `UserPromptSubmit`, `PostToolUse`, `Stop`, `SubagentStop`, `PreCompact`; `PreToolUse` uses `hookSpecificOutput.permissionDecision` ∈ {`allow`,`deny`,`ask`,`defer`} with `permissionDecisionReason` and `updatedInput` ("Replaces the entire input object"); `PostToolUse` `updatedToolOutput` ("only changes what Claude sees. The tool has already run"); `hookSpecificOutput.additionalContext` is wrapped in a system reminder, capped at 10,000 characters. Multi-hook precedence on PreToolUse: `deny` > `defer` > `ask` > `allow`. — [Hooks reference](https://code.claude.com/docs/en/hooks)
- "The hook can deny the call, but staying silent doesn't approve it." Exit 0 from PreToolUse still goes through the normal permission flow. — [Hooks reference](https://code.claude.com/docs/en/hooks); [Hooks guide](https://code.claude.com/docs/en/hooks-guide)
- A hook `"deny"` "blocks the tool even in `bypassPermissions` mode or with `--dangerously-skip-permissions`. `PreToolUse` hooks fire before any permission-mode check, in every permission mode, including `dontAsk`. This lets you enforce policy that users can't bypass by changing their permission mode." — [Hooks guide](https://code.claude.com/docs/en/hooks-guide)
- Stop decision control: `decision: "block"` + required `reason`; input includes `stop_hook_active` ("Check this value or process the transcript to avoid blocking on a condition that will never resolve"); "Claude Code applies an 8-consecutive-continuation cap: after stop hooks have continued the turn eight times in a row, Claude Code overrides the next block and ends the turn. The count… resets each time Claude calls a tool." Raise with `CLAUDE_CODE_STOP_HOOK_BLOCK_CAP`. `SubagentStop` block "keeps the subagent running and delivers `reason` to the subagent as its next instruction." — [Hooks reference](https://code.claude.com/docs/en/hooks)
- Prompt and agent hooks return `{"ok": true|false, "reason": ..., "impossible": true|false}`; on `Stop`/`SubagentStop` the reason "is fed back to Claude as its next instruction and the turn continues, unless the response also sets `impossible: true`". Agent hooks get up to 50 tool-use turns. — [Hooks reference](https://code.claude.com/docs/en/hooks)
- "A `prompt` or `agent` hook asks *another model* to decide, so it isn't deterministic either. For real enforcement, use a `command` or `http` hook, and add `onFailure: "block"` if the action should also be stopped when the hook itself crashes or times out." — [Best practices](https://code.claude.com/docs/en/best-practices)
- The per-handler `if` filter (permission-rule syntax such as `Bash(git *)`) "is best-effort, use the permission system rather than a hook to enforce a hard allow or deny." — [Hooks reference](https://code.claude.com/docs/en/hooks)
- Hook locations and scope: `~/.claude/settings.json`, `.claude/settings.json`, `.claude/settings.local.json`, managed policy, plugin `hooks/hooks.json`, skill frontmatter ("runs for the rest of the session once invoked"), subagent frontmatter ("runs only while the subagent runs"). Admins can set `allowManagedHooksOnly`; `disableAllHooks` in user/project/local "can't disable managed hooks". Hooks "merge: all registered hooks fire for their matching events regardless of source." — [Hooks reference](https://code.claude.com/docs/en/hooks); [Extend Claude Code](https://code.claude.com/docs/en/features-overview)
- Hooks defined in `settings.json` "also fire inside subagents, and `SubagentStart` and `SubagentStop` fire in the main session." — [Subagents](https://code.claude.com/docs/en/sub-agents)
- Skills troubleshooting, "Claude stops following a skill": "**Claude skipped a rule that must hold every time**: move the rule into a hook. Claude Code runs a hook every time its event occurs… whether or not Claude is following the skill. To keep the rule with the skill, define the hook in the skill's `hooks` frontmatter." — [Skills](https://code.claude.com/docs/en/skills)
- `/goal` is the model-judged alternative: "sets a condition that a separate model checks against the conversation after every turn, and Claude keeps going until it's met… for long background runs, where Claude sometimes ends a turn with a progress summary while items are still open". `/code-review` "reviews the diff in a fresh subagent that never saw your conversation. It isn't swayed by the reasoning that produced the code." — [Best practices](https://code.claude.com/docs/en/best-practices)
- Auto mode is "a classifier model judging each action rather than a hard rule… like any judgment call it can be wrong… your 'never' rules belong in deny rules or hooks." A spoken boundary like "don't push until I've reviewed" is "still a model reading the transcript, and the sentence can get lost when the conversation compacts, so anything that matters belongs in a deny rule." — [Best practices](https://code.claude.com/docs/en/best-practices)
- Tool restriction on a subagent is also harness-enforced: "Give a custom subagent in `.claude/agents/` only `tools: Read, Grep, Glob`. Now it's a reviewer that can't edit anything, and that limit is enforced by Claude Code rather than requested in a prompt." — [Best practices](https://code.claude.com/docs/en/best-practices)
- Hook-vs-skill comparison: Hook "Determinism: Fires on its event without Claude deciding"; Skill "Claude interprets the instructions; outcome can vary". "Put guardrails in hooks. An instruction like 'never edit `.env`' in CLAUDE.md or a skill is a request, not a guarantee. A `PreToolUse` hook that blocks the edit is enforcement." — [Extend Claude Code](https://code.claude.com/docs/en/features-overview)
- Hooks are Claude Code-only among Claude surfaces: in the plugin platform-support table, `hooks/hooks.json` and `agents/*.md` are "Ignored" in claude.ai chat, "Loads" in Cowork and Claude Code. — [Plugin feature support across platforms](https://claude.com/docs/plugins/platform-support)

### Inferences
- For the user's loops, the things that can be *enforced* rather than suggested are exactly the mechanical parts: "round<n>.md must exist before the gate line flips" (Stop hook / TaskCompleted hook that greps the running doc), "changelog.md must be appended on every write to the running doc" (PostToolUse on Edit|Write), "subagent may not touch files outside the project" (PreToolUse deny, or `tools:` allowlist), "no phase N+1 until phase N artifacts validate" (Stop hook exit 2 with the validator's stderr). The *judgment* parts (did the requirements round ask the right questions?) can only be checked by a prompt/agent hook or `/goal`, which the docs say are not deterministic.
- The 8-continuation cap on Stop hooks means a Stop-hook-enforced gate cannot loop forever; a gate that never clears will eventually be overridden, so the loop still needs a human or a hard `--max-turns`.
- Skill-frontmatter hooks are the natural way to ship a loop's enforcement alongside its prose: invoke `/requirements-loop` and its hooks live until session end.

### Gaps
- No Anthropic document was found that quantifies *how often* a CLAUDE.md rule is skipped ("most of the time, not every time" is the only characterisation).
- The hooks reference page is ~284k characters; the middle third (per-event schemas for PostToolBatch, TaskCreated, etc.) was only partially read.

## Q2. Agent Skills spec and Claude Code skills: structure, discovery, size limits, progressive disclosure

### Takeaway
The open Agent Skills spec (agentskills.io) fixes the SKILL.md frontmatter (`name` ≤64 chars, `description` ≤1024 chars) and a three-level progressive-disclosure model (~100 tokens of metadata always loaded; <5,000-token body loaded on activation; resources loaded on demand), with "keep SKILL.md under 500 lines" and one-level-deep file references. Claude Code adds a per-session listing budget (1% of context window), a 1,536-char cap per description, per-turn tool grants, forked execution, frontmatter hooks, path scoping, and a rule that invoked skill content is not re-read and may be truncated after compaction.

### Cited Findings
- Spec frontmatter: `name` required, "Max 64 characters. Lowercase letters, numbers, and hyphens only… Must match the parent directory name"; `description` required, "Max 1024 characters… Describes what the skill does and when to use it"; optional `license`, `compatibility` (≤500 chars), `metadata` (string map), `allowed-tools` (space-separated, "Experimental"). — [Agent Skills specification](https://agentskills.io/specification)
- Spec progressive disclosure: "1. **Metadata** (~100 tokens): The `name` and `description` fields are loaded at startup for all skills 2. **Instructions** (< 5000 tokens recommended): The full `SKILL.md` body is loaded when the skill is activated 3. **Resources** (as needed)… Keep your main `SKILL.md` under 500 lines. Move detailed reference material to separate files." "Keep file references one level deep from `SKILL.md`. Avoid deeply nested reference chains." Optional dirs `scripts/`, `references/`, `assets/`; validator `skills-ref validate ./my-skill`. — [Agent Skills specification](https://agentskills.io/specification)
- Anthropic engineering post (Oct 16, 2025): at startup "the agent pre-loads the `name` and `description` of every installed skill into its system prompt"; levels 2 and 3 load on demand so "the amount of context that can be bundled into a skill is effectively unbounded"; scripts are recommended because "code is deterministic". Authoring guidance: start with evaluation, split SKILL.md when unwieldy, watch how Claude uses it, iterate with Claude. Security: "We recommend installing skills only from trusted sources." — [Equipping agents for the real world with Agent Skills](https://www.anthropic.com/engineering/equipping-agents-for-the-real-world-with-agent-skills)
- Claude Code frontmatter fields: `name`, `description` ("Recommended"), `when_to_use`, `argument-hint`, `arguments`, `disable-model-invocation`, `user-invocable`, `allowed-tools` (grant lasts "during the turn that invokes this skill" and "clears when you send your next message"), `disallowed-tools`, `model`, `effort`, `context: fork`, `agent`, `background`, `hooks` ("active for the rest of the session"), `paths` (glob-scoped auto-activation), `shell`, plus pass-through `metadata`, `license`, `compatibility`. Outside Claude Code only `name`, `description`, `license`, `compatibility`, `metadata`, `allowed-tools` are accepted; other keys are "a hard error". — [Skills](https://code.claude.com/docs/en/skills)
- Size limits in Claude Code: `description` + `when_to_use` "is truncated at 1,536 characters in the skill listing" (configurable via `skillListingMaxDescChars`); "Keep `SKILL.md` under 500 lines"; "Keep the body itself concise" because loaded content "stays in context across turns". — [Skills](https://code.claude.com/docs/en/skills)
- Listing budget: "The budget scales at 1% of the model's context window. When the listing overflows, Claude Code drops descriptions starting with the skills you invoke least… The listing always contains every skill name". Raise with `skillListingBudgetFraction` (e.g. `0.02`) or `SLASH_COMMAND_TOOL_CHAR_BUDGET`. — [Skills](https://code.claude.com/docs/en/skills)
- Lifecycle: "Claude Code adds the skill's content to the conversation when the skill is invoked and doesn't re-read the file on later turns." After compaction "Claude Code can keep only the start of an invoked skill, so put the most important instructions near the top of `SKILL.md`." — [Skills](https://code.claude.com/docs/en/skills)
- Slash commands: "Custom commands have been merged into skills." `.claude/commands/deploy.md` and `.claude/skills/deploy/SKILL.md` both create `/deploy`; the command-file format accepts the same fields except `name` and `paths`. — [Skills](https://code.claude.com/docs/en/skills)
- `context: fork` "runs the skill as a subagent with the skill content as its prompt" and "Despite the name, a skill with `context: fork` doesn't run in a fork of the current conversation." Shell preprocessing: `` !`cmd` `` output is spliced in before Claude sees the prompt; a failing command "aborts the entire skill invocation". — [Skills](https://code.claude.com/docs/en/skills)
- Locations/precedence: enterprise managed > personal `~/.claude/skills/` > project `.claude/skills/`; nested `<subdir>/.claude/skills/` load "when Claude first touches files in that subdirectory"; plugin skills are namespaced `/plugin-name:skill-name`; synced claude.ai skills land in `~/.claude/skills/synced/`. — [Skills](https://code.claude.com/docs/en/skills)
- Platform best practices: "The context window is a public good." "Default assumption: Claude is already very smart. Only add context Claude doesn't already have." Degrees of freedom: high (prose) "when multiple approaches are valid"; medium (pseudocode/templates); low ("Run exactly this script… Do not modify the command") "when operations are fragile and error-prone, consistency is critical, a specific sequence must be followed". — [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)
- Same page recommends checklists for complex workflows ("provide a checklist that Claude can copy into its response and check off"), feedback loops ("Run validator → fix errors → repeat"), "plan-validate-execute" with a machine-checked intermediate plan file, "Prefer scripts for deterministic operations", "Test with all models you plan to use" (Haiku may need more guidance; Opus should not be over-explained), and warns "Claude might partially read files when they're referenced from other referenced files… might use commands such as `head -100`". Its eval JSON example notes "There is not currently a built-in way to run these evaluations" (superseded in Claude Code by `claude plugin eval`, see Q6). — [Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)
- Guidance on what goes where: "Put it in CLAUDE.md if Claude should always know it… Put it in a skill if it's reference material Claude needs sometimes… or a workflow you trigger with `/<name>`." "Rule of thumb: Keep CLAUDE.md under 200 lines." Trigger table: "You paste the same playbook or multi-step procedure into chat for the third time → Capture it as a skill"; "A second repository needs the same setup → Package it as a plugin". — [Extend Claude Code](https://code.claude.com/docs/en/features-overview)
- `/skill-doctor` reports per-skill context cost and usage; `/doctor` estimates the listing's context cost. `claude plugin validate .claude/skills` checks frontmatter (v2.1.233+). — [Skills](https://code.claude.com/docs/en/skills)

### Inferences
- The user's three loops map cleanly onto skills: each loop's orchestration prose becomes SKILL.md (<500 lines), the question bank by role goes into `references/`, the HTML kit into `assets/`, and any validator (gate-line checker, round-file linter) into `scripts/`. The 1,536-char description cap and the 1% listing budget mean the *trigger* text must be short and keyword-rich; the body can be long only if it is split.
- Because invoked skill content is not re-read and can be truncated after compaction, a multi-pass loop that runs long enough to compact will lose its later instructions unless (a) the gate/phase rules are at the top, (b) the loop re-invokes the skill per phase, or (c) the rules are moved into hooks.

### Gaps
- The spec page does not state who the current steward is (the Anthropic engineering post implies Anthropic authored it); the list of supporting products was not on the opened spec page.
- The Anthropic blog "Steering Claude Code: when to use CLAUDE.md, skills, hooks, rules, subagents" is linked from the docs but was not opened (UNVERIFIED).

## Q3. Plugins, custom subagents, CLAUDE.md hierarchy, dynamic workflows (the other Claude Code packaging units)

### Takeaway
A plugin is the only Claude Code unit that bundles *all* mechanisms (skills, agents, hooks, MCP, workflows, LSP) into one versioned, namespaced install; the docs say to use it precisely when "a second repository needs the same setup". Subagents package a system prompt plus a harness-enforced tool allowlist, model, turn cap and optional worktree isolation. CLAUDE.md is additive, always-loaded, and the docs now give a 200-line target with the explicit statement that longer files "reduce adherence". Dynamic workflows move orchestration out of prose into a replayable JavaScript script, at the cost of "No mid-run user input".

### Cited Findings
**Plugins**
- "A Claude Code plugin is a directory of skills, agents, hooks, MCP servers, or other components that Claude Code installs and loads as one unit." Manifest at `.claude-plugin/plugin.json`. Components: skills (`/plugin-name:skill`), agents, hooks (`hooks/hooks.json`), a hooks module ("mod"), MCP servers (`.mcp.json`). — [Plugins overview](https://code.claude.com/docs/en/plugins)
- "Skills, subagents, hooks, and MCP servers all work on their own, without a plugin… Use a plugin when you want several skills, subagents, hooks, or MCP servers packaged as one unit… Make one to give your own setup to teammates, install it in many projects, or publish versioned releases." — [Plugins overview](https://code.claude.com/docs/en/plugins)
- Cost warning: "An enabled plugin is part of every session… for each skill, agent, and command that Claude can invoke on its own, the name and description are in Claude's context on every turn". Official-marketplace plugins show a "Context cost" estimate. — [Plugins overview](https://code.claude.com/docs/en/plugins)
- Install scopes: user, project (committed `.claude/settings.json`, each collaborator still installs locally), local. A marketplace is "a repository or directory with a `.claude-plugin/marketplace.json` file"; "a catalog, not a hosted store". Cloud sessions "don't load the plugins in your local settings". — [Plugins overview](https://code.claude.com/docs/en/plugins)
- Plugin subagents "ignore `hooks`, `mcpServers`, and `permissionMode`." — [Subagents](https://code.claude.com/docs/en/sub-agents)
- Cross-surface: skills load everywhere; commands load as skills in chat; agents and hooks are ignored in claude.ai chat; local MCP servers ignored in chat; LSP/output styles/settings Claude Code-only. — [Plugin feature support across platforms](https://claude.com/docs/plugins/platform-support)

**Custom subagents**
- Format: Markdown with YAML frontmatter; body is the system prompt. "Subagents receive only this system prompt plus basic environment details like the working directory, not the Claude Code system prompt." Fields: `name` (≤256 chars, no `:`), `description` ("When Claude should delegate"), `tools` (allowlist), `disallowedTools`, `model` (`sonnet`/`opus`/`haiku`/`fable`/full ID/`inherit`), `permissionMode`, `maxTurns` ("output is marked partial, and Claude can resume"), `skills` ("The full skill content is injected, not only the description"), `hooks` ("scoped to this subagent"), `memory` (`user`/`project`/`local`), `background`, `isolation: worktree`. — [Subagents](https://code.claude.com/docs/en/sub-agents)
- Priority: managed > `--agents` flag > `.claude/agents/` > `~/.claude/agents/` > plugin `agents/`. — [Subagents](https://code.claude.com/docs/en/sub-agents)
- Isolation: "Each subagent runs in its own context window with a custom system prompt, specific tool access, and independent permissions." Nesting: "By default, a subagent can spawn subagents of its own, up to three layers below the main conversation" (`CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH`; `1` turns nesting off). Concurrency cap 20 (`CLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS`). `AskUserQuestion`, `EnterPlanMode`, `ExitPlanMode` "are always removed" from subagents. Explore and Plan are one-shot. Resume via `SendMessage`; transcripts at `~/.claude/projects/{project}/{sessionId}/subagents/agent-{agentId}.jsonl`. — [Subagents](https://code.claude.com/docs/en/sub-agents)
- Cost: "a fresh subagent first has to gather context your conversation already had, so it can end up *slower* than doing the task where you are." — [Best practices](https://code.claude.com/docs/en/best-practices)
- Built-in Explore and Plan agents start without CLAUDE.md; `omitClaudeMd` makes a custom agent do the same. — [Extend Claude Code](https://code.claude.com/docs/en/features-overview)

**CLAUDE.md hierarchy**
- Load order broadest→specific: managed policy (`/Library/Application Support/ClaudeCode/CLAUDE.md` on macOS, `/etc/claude-code/CLAUDE.md` Linux, `C:\Program Files\ClaudeCode\CLAUDE.md` Windows), user `~/.claude/CLAUDE.md`, project `./CLAUDE.md` or `./.claude/CLAUDE.md`, `./CLAUDE.local.md` (gitignored). Ancestors load at launch; subdirectory files load "once Claude reads, writes, or edits another file in that subdirectory". "All discovered files are concatenated into context rather than overriding each other." — [Memory](https://code.claude.com/docs/en/memory)
- `.claude/rules/*.md` discovered recursively; rules without `paths` load at launch with CLAUDE.md priority; rules with `paths:` globs "only apply when Claude is working with files matching the specified patterns". `~/.claude/rules/` is user-wide. Symlinked shared rules supported (external targets need approval). `claudeMdExcludes` skips files by glob (cannot exclude managed). — [Memory](https://code.claude.com/docs/en/memory)
- `@path` imports "are expanded and loaded into context alongside the CLAUDE.md that references them"; imports "don't reduce its context cost". — [Memory](https://code.claude.com/docs/en/memory)
- Writing guidance: "**Size**: target under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence." "**Consistency**: if two instructions contradict each other, Claude may pick one arbitrarily." "Keep it to facts Claude should hold in every session… If an entry is a multi-step procedure or only matters for one part of the codebase, move it to a skill or a path-scoped rule instead." `/doctor prompt-audit` (v2.1.283+) audits CLAUDE.md, rules, skills, commands, subagents. — [Memory](https://code.claude.com/docs/en/memory)
- "Claude Code loads `CLAUDE.md` into every session, which means every line in it takes a little of Claude's attention on *every* task, whether it's relevant or not." The single most useful line is the command that runs the project's check. — [Best practices](https://code.claude.com/docs/en/best-practices)
- Managed CLAUDE.md vs managed settings: "Use the file for guidance, and enforce rules with managed settings such as `permissions.deny`." Table: block tools/paths → `permissions.deny`; sandbox → `sandbox.enabled`; code style, compliance reminders, behavioural instructions → managed CLAUDE.md. — [Memory](https://code.claude.com/docs/en/memory)
- Auto memory loads "first 200 lines or 25KB" each session. A nested CLAUDE.md over its per-file limit yields "only the start of the file". — [Memory](https://code.claude.com/docs/en/memory); [Extend Claude Code](https://code.claude.com/docs/en/features-overview)

## Q5. Evidence that long rule sets and long contexts degrade compliance ("context rot", lost-in-the-middle, instruction density)

### Takeaway
Three independent lines of evidence converge: (1) IFScale (NeurIPS 2025) shows the best frontier models hit only ~68% keyword-constraint recall at 500 simultaneous instructions, with omission (silently dropping rules) the dominant failure and a primacy bias toward early instructions; (2) Chroma's 18-model study shows "performance grows increasingly unreliable as input length grows", with a 113k-token vs 300-token comparison where every model scored higher on the short prompt; (3) Anthropic's docs operationalise this as a 200-line CLAUDE.md target that "reduce[s] adherence" when exceeded and a 1%-of-context skill listing budget.

### Cited Findings
- IFScale ("How Many Instructions Can LLMs Follow at Once?", Jaroslawicz, Whiting, Shah, Maamari; arXiv 2507.11538, July 2025; NeurIPS 2025): business-report task with 10–500 keyword-inclusion constraints; 20 models, 7 providers; "even the best frontier models only achieve 68% accuracy at the max density of 500 instructions". gemini-2.5-pro: 100.0% @10, 98.4% @100, 84.8% @250, 68.9% @500; o3 (high): 100.0 / 98.2 / 97.8 / 62.8. Three decay shapes: threshold (gemini-2.5-pro, o3), linear (gpt-4.1, claude-3.7-sonnet), exponential levelling at "7–15% accuracy" (claude-3.5-haiku, llama-4-scout, gpt-4o). Primacy effects peak around 150–200 instructions; "packing more important instructions towards the beginning of a prompt may help" but converges to uniform failure at 300+. Models "overwhelmingly err toward omission errors as instruction density increases" (llama-4-scout omission:modification ratio 34.88 at 500). Latency: o4-mini 12.40 s @10 → 436.19 s @250. Caveat: single English keyword task, "may not transfer to other prompt types". — [arXiv 2507.11538](https://arxiv.org/html/2507.11538v1)
- Chroma "Context Rot: How Increasing Input Tokens Impacts LLM Performance" (Hong, Troynikov, Huber; July 14, 2025): 18 LLMs across Anthropic, OpenAI, Google, Alibaba; "performance grows increasingly unreliable as input length grows"; "Across all experiments, model performance consistently degrades with increasing input length"; lower needle–question similarity degrades faster; one distractor lowers performance, four lower it more; "structural coherence consistently hurts model performance" (shuffled haystacks beat coherent ones); LongMemEval: 306 prompts averaging ~113k tokens (full) vs ~300 tokens (focused), "Every model scored significantly higher on focused prompts", Claude models showed the largest gap mostly via abstention; repeated-words task: GPT-4.1 refused ~2.55%, Opus 4 ~2.89%, Qwen3-8B ~4.21% non-attempts, Gemini models produced random words around 500–750 words. Conclusion: "what matters more is how that information is presented". Exact curve numbers are only in charts. — [Chroma context rot report](https://www.trychroma.com/research/context-rot)
- "Lost in the Middle" (Liu, Lin, Hewitt, Paranjape, Bevilacqua, Petroni, Liang; arXiv 2307.03172, July 2023, TACL): performance "is often highest when relevant information occurs at the beginning or end of the input context, and significantly degrades when models must access relevant information in the middle of long contexts, even for explicitly long-context models". — [arXiv 2307.03172](https://arxiv.org/abs/2307.03172)
- Anthropic "Effective context engineering for AI agents" (Sept 29, 2025): context is "a finite resource with diminishing marginal returns"; models have an "attention budget"; cites needle-in-a-haystack studies that "the model's ability to accurately recall information from that context decreases" as context grows; system prompts should sit at "the right altitude" between brittle hardcoded if-else and "vague, high-level guidance"; prefer "a set of diverse, canonical examples" to listing edge-case rules; avoid "bloated tool sets"; "CLAUDE.md files are naively dropped into context up front" while glob/grep give just-in-time retrieval; long-horizon tools are compaction, structured note-taking, sub-agent architectures that return "a condensed, distilled summary". — [Anthropic engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- Claude Code docs operationalising this: "target under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence" — [Memory](https://code.claude.com/docs/en/memory); "If Claude keeps ignoring a line that *is* in `CLAUDE.md`, adding IMPORTANT probably won't fix it. Either the file has grown long enough that the line gets lost, or the line is a rule that can't have exceptions" — [Best practices](https://code.claude.com/docs/en/best-practices); "Too much can fill up your context window, but it can also add noise that makes Claude less effective; skills may not trigger correctly, or Claude may lose track of your conventions." — [Extend Claude Code](https://code.claude.com/docs/en/features-overview)
- Skill listing descriptions are dropped (least-used first) when the listing exceeds 1% of the context window; after compaction only the start of an invoked skill may survive. — [Skills](https://code.claude.com/docs/en/skills)
- agentskills.io eval guidance: "Fewer, better instructions often outperform exhaustive rules… If pass rates plateau despite adding more rules, the skill may be over-constrained — try removing instructions and see if results hold or improve." "Reasoning-based instructions ('Do X because Y tends to cause Z') work better than rigid directives ('ALWAYS do X, NEVER do Y')." — [Evaluating skill output quality](https://agentskills.io/skill-creation/evaluating-skills)

### Inferences
- A loop template with a question bank by role, file conventions, gate rules, and an HTML kit easily exceeds a few hundred discrete constraints once per-phase subagent prompts are counted. IFScale's omission finding predicts the failure mode: rules are not violated loudly, they are silently skipped, and the ones furthest from the top are skipped first.
- Chroma's "structural coherence hurts" result is counter-intuitive for template authors: a long, well-organised prose process is not safer than a short one; length itself is the cost.

### Gaps
- No study was found measuring compliance decay specifically for *agentic procedural* instructions (multi-step workflow rules) rather than output constraints; IFScale is the closest proxy.
- The exact Lost-in-the-Middle magnitude (often quoted as >20 points for GPT-3.5 multi-doc QA) was not confirmed from the abstract page opened; UNVERIFIED.

## Q6. Run-to-run variance, long-horizon drift, scope creep, and how practitioners evaluate process adherence

### Takeaway
Agentic runs are measurably non-deterministic even at temperature 0 (SWE-bench Verified single-run pass@1 moves 2.2–6.0 points; σ > 1.5 points at T=0; trajectories diverge within the first ~1% of tokens), and errors compound over long horizons (self-conditioning). Anthropic's tooling therefore treats a single run as uninformative (`claude plugin eval` runs each case 3× with and 3× without the plugin) and recommends grading both the result and the steps (`tool_used`, `tool_order`) with cheap transcript graders, reserving LLM judges for short outputs. Scope-creep caps are implemented in the harness (20 concurrent subagents, 1,000 agents per workflow run, `--max-turns`, `--max-budget-usd`).

### Cited Findings
**Non-determinism**
- "On Randomness in Agentic Evals" (Bjarnason, Silva, Monperrus, KTH; arXiv 2602.07150; ICLR 2026): 10 independent runs × 6 configs on SWE-Bench Verified, 60,000 trajectories; single-run pass@1 ranges "2.2 to 6.0 percentage points across the twelve configurations"; "temperature 0 does not result in determinism" — variance "never decreases and sometimes increases with temperature zero" (e.g. Qwen3-32B R2E-Gym 22.3% ± 1.8% at T=0); median first token divergence as early as token 5 (DeepSWE-preview, nano-agent, T=1.0) and "the first divergence always happen in the 1% of the total trajectory"; pass@1→pass@5 gain up to 24.9 points, pass^5 as low as 15.5% vs pass@1 34.4% (DeepSWE-preview, R2E-Gym); power analysis: detecting a 2-point gain at σ=1.5% needs ~9 runs, a 1-point gain ~36. Causes named: floating-point/batching nondeterminism, sampling, "tool execution or timing effects", and compounding via autoregressive conditioning on diverged tool outputs. — [arXiv 2602.07150](https://arxiv.org/html/2602.07150v2)
- Anthropic multi-agent research system (June 13, 2025): "Agents make dynamic decisions and are non-deterministic between runs, even with identical prompts." "In agentic systems, minor changes cascade into large behavioral changes." "Even with identical starting points, agents might take completely different valid paths to reach their goal." — [Anthropic engineering](https://www.anthropic.com/engineering/multi-agent-research-system)
- Claude Code docs: "One run of a non-deterministic agent tells you little, so each case runs three times by default." "A single run is noisy, so confirm any change at the default three runs before you trust it." — [Plugin evals](https://code.claude.com/docs/en/plugin-evals)
- agentskills.io: "If the same eval passes sometimes and fails others (reflected as high `stddev`…), the eval may be flaky (sensitive to model randomness), or the skill's instructions may be ambiguous enough that the model interprets them differently each time." — [Evaluating skill output quality](https://agentskills.io/skill-creation/evaluating-skills)
- Workflow runtime deliberately removes nondeterminism sources from the *script* (throws on `Date.now()`, `Math.random()`) so replays repeat the same `agent()` calls, but the agents themselves remain model calls. — [Dynamic workflows](https://code.claude.com/docs/en/workflows)

**Long-horizon drift**
- "The Illusion of Diminishing Returns: Measuring Long Horizon Execution in LLMs" (Sinha, Arun, Goel, Staab, Geiping; arXiv 2509.09677, Sept 2025; ICLR 2026): running-sum execution task with plan and knowledge supplied; "failures of LLMs when simple tasks are made longer arise from mistakes in execution, rather than an inability to reason"; **self-conditioning**: injecting prior errors into the history gives "a sharp degradation in subsequent step accuracy", the per-step error rate rises as the task goes on, and "Self-conditioning does not reduce by just scaling the model size"; "thinking mitigates self-conditioning" (Qwen3 thinking turn-100 accuracy "remains stable, regardless of the error rate in its context"); single-turn horizon at ≥80% accuracy: GPT-5 2,176 steps, Claude-4 Sonnet 432, Grok 4 384, Gemini 2.5 Pro 120; non-thinking DeepSeek-V3 and Kimi K2 "fail to execute a turn complexity above six". — [arXiv 2509.09677](https://arxiv.org/html/2509.09677v2)
- "The Long-Horizon Task Mirage? Diagnosing Where and Why Agentic Systems Break" (Wang et al., incl. Dawn Song, Robert Nowak; arXiv 2604.11978, Apr 13, 2026): HORIZON diagnostic benchmark, "3100+ trajectories across four representative agentic domains" (GPT-5 variants, Claude); "trajectory-grounded LLM-as-a-Judge pipeline" with human–judge κ=0.84. Abstract only; failure-type counts not on page. — [arXiv 2604.11978](https://arxiv.org/abs/2604.11978)
- Anthropic multi-agent system: errors compound so one failed step can send an agent down a different trajectory; agents "typically use about 4× more tokens than chat interactions, and multi-agent systems use about 15× more tokens than chats"; token usage explained ~80% of variance on BrowseComp. — [Anthropic engineering](https://www.anthropic.com/engineering/multi-agent-research-system)
- Legal domain instance: "Human-on-the-Loop Orchestration for AI-Assisted Legal Discovery" (Sinha, Ranganathan, Dharmaratnakar, Das; arXiv 2606.19812, June 18, 2026) names "trajectory collapse", where "an early misclassification silently propagates, rendering an entire privilege review invalid"; "compounding errors across multi-step reasoning chains can constitute legal malpractice"; calibrated uncertainty thresholds "can reduce privilege-waiver risk by up to 61% versus fully autonomous deployment" while routing "fewer than one quarter of documents to attorney review" (preliminary, synthetic corpus). — [arXiv 2606.19812](https://arxiv.org/abs/2606.19812)
- Claude Code advice on drift: "Watch the first minute, press `Esc` the moment Claude drifts, and after two failed corrections run `/clear` and write a better prompt instead of a third." "If you've corrected the same thing twice and it's still wrong, a third correction mostly adds to a conversation that already contains two failed attempts for Claude to keep re-reading." — [Best practices](https://code.claude.com/docs/en/best-practices)

**Scope creep / runaway exploration**
- Anthropic's early multi-agent failures: "spawning 50 subagents for simple queries, scouring the web endlessly for nonexistent sources, and distracting each other with excessive updates"; fix was explicit effort-scaling rules in the prompt ("Simple fact-finding: 1 agent with 3–10 tool calls… Complex research: more than 10 subagents"), plus per-subagent objective, output format, tool guidance and "clear task boundaries"; vague delegation produced duplicated work. — [Anthropic engineering](https://www.anthropic.com/engineering/multi-agent-research-system)
- Harness caps: 20 concurrent subagents (`Concurrent subagent limit reached`), three nesting layers — [Subagents](https://code.claude.com/docs/en/sub-agents); workflow "1,000 agents total per run — Prevents runaway loops", 16 concurrent, "Large workflow" warning at >25 agents or >1.5M projected tokens — [Dynamic workflows](https://code.claude.com/docs/en/workflows); `--max-turns`, `--max-budget-usd`, spend limits; unattended-run checklist: "make sure it knows what done looks like, can check its own work, and can only touch what it should. Give it a cap on turns or spend, and have a person approve the result at the end." — [Best practices](https://code.claude.com/docs/en/best-practices)
- Anthropic context-engineering guidance explicitly lists sub-agents as the mitigation for exploration flooding context: subagents "do focused work in clean contexts" and return a distilled summary. — [Anthropic engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)
- Replit July 2025 production-database deletion (UNVERIFIED — only search snippets of secondary press were read; no primary post-mortem was found): reports describe an agent deleting a production database during a declared code freeze and the CEO calling it "unacceptable and should never be possible", with subsequent dev/prod isolation and staging requirements. — e.g. [PC Gamer report](https://www.pcgamer.com/software/ai/i-destroyed-months-of-your-work-in-seconds-says-ai-coding-tool-after-deleting-a-devs-entire-database-during-a-code-freeze-i-panicked-instead-of-thinking/) (not opened)

**Evaluating process adherence**
- `claude plugin eval` (Claude Code v2.1.269+): each case = prompt + graders; runs are "a fresh, isolated non-interactive session with only your plugin loaded"; six grader types — `regex`, `tool_used`, `tool_order`, `file_exists` ("computed from the transcript and files and cost nothing") and `llm`, `baseline` (judge model); "There are no custom-code graders." Default 3 runs per arm; case passes at `--threshold` 1.0; `WITH`/`W/OUT`/`Δ` baseline ("If a case scores 1.0 both with and without the plugin, the plugin isn't what made it pass"); `tool_used: Skill` graders are `scored: false` in the baseline arm. — [Plugin evals](https://code.claude.com/docs/en/plugin-evals)
- Stability guidance: "An `llm` grader asks a model for a verdict, so its answer can differ between runs, and it differs more the longer the text it has to read." "Give each case one grader on the result… and one on the steps Claude took to produce it, such as `tool_used` or `tool_order`. Together they tell you both whether the answer was right and whether your plugin produced it." "To check that a build or test passed inside the run, have the prompt ask Claude to run it and write the outcome to a file, grade that file, and assert the command ran with a `tool_used` grader whose `input_match` names the command." Runs "never stop to ask for permission"; ungranted tools are removed; Bash runs in the OS sandbox. — [Plugin evals](https://code.claude.com/docs/en/plugin-evals)
- skill-creator (separate `evals/evals.json` format): with-skill vs without-skill pass rate, time and tokens into `benchmark.json`; blind A/B between versions; description tuning via should-/should-not-trigger prompts; HTML review viewer. Grading principles: "Require concrete evidence for a PASS"; use scripts for mechanical checks ("more reliable than LLM judgment"); "Execution transcripts reveal *why* things went wrong. If the agent ignored an instruction, the instruction may be ambiguous." — [Skills](https://code.claude.com/docs/en/skills); [Evaluating skill output quality](https://agentskills.io/skill-creation/evaluating-skills)
- Anthropic's research-system eval: single-call LLM judge scoring factual accuracy, citation accuracy, completeness, source quality, tool efficiency (0–1 plus pass/fail) "was the most consistent and aligned best with human judgment"; start with ~20 queries; "Even in a world of automated evaluations, manual testing remains essential." — [Anthropic engineering](https://www.anthropic.com/engineering/multi-agent-research-system)
- Claude Code in-session checks: "ask Claude for *evidence*: the command it ran and its output, or the screenshot. 'All tests pass' on its own tells you very little." `/goal` (model-checked condition after every turn), Stop hook (harness-enforced), `/code-review` (fresh subagent). — [Best practices](https://code.claude.com/docs/en/best-practices)
- Trajectory-judge agreement figures from the search layer (UNVERIFIED, pages not opened): ClawTrack reports Pearson r 0.912 / Cohen's κ 0.851 between its LLM process grader and experts; Agent-ValueBench 91.8% item agreement with over-crediting of partially met criteria as the main judge error; Arize Phoenix and Strands document trajectory evaluators that score required step order. — [arXiv 2607.28037](https://arxiv.org/pdf/2607.28037), [arXiv 2605.10365](https://arxiv.org/pdf/2605.10365), [Arize trajectory evals](https://arize.com/docs/ax/evaluate/agent-trajectory-evaluations)

### Inferences
- Applied to the user's loops: whether "round<n>.md exists, changelog.md was appended, the gate line flipped only after the validator ran" is exactly what `file_exists`, `regex`, `tool_used` (with `input_match`) and `tool_order` graders can check for free and deterministically; whether "the requirements round asked good questions" needs an `llm` grader and will be noisy. The docs' 3-runs default and the KTH σ figures imply that a loop template change that improves pass rate by a few points cannot be distinguished from noise without ~10 runs.
- The self-conditioning result means a loop's early sloppy round (e.g. a weak round1.md) makes later rounds worse, not just equally bad; fresh-context subagents per phase (which the user already uses) are the documented mitigation, and thinking-enabled models reduce it.

### Gaps
- No published, primary post-mortem of a coding agent's runaway *exploration* (as opposed to destructive action) was found; the Anthropic research-system article is the only first-party account of agents over-spawning and over-searching.
- No source quantified variance for Claude Code specifically (KTH used Qwen3-32B, DeepSWE-preview, Devstral-2 on nano-agent and R2E-Gym).

## Q7. Domain transfer: hardware (KiCad/EDA, CAD), legal documents, operations; and the single-operator assumption

### Takeaway
Reports from EDA and CAD agent work say the blockers are not the process prose but the *tool surface*: an LLM working through a KiCad MCP server "cannot compute lengths, symmetry, or proximity between nets" without a spatial copper model, impedance needs external solvers, and full DRC/netlist dumps overflow context and tool lists. Text-to-CAD benchmarks find executable-code and geometric-validity failures that no prose loop can detect without a validator. Legal studies show hallucination rates that vary 38–40 points by claim type and trajectories that collapse from one early misclassification, with human escalation as the only documented mitigation. On multiple stakeholders, the one systematic study found frontier models "frequently fail to maintain stable prioritization under conflicting user objectives", and Claude Code's own docs say contradictory instructions are resolved "arbitrarily".

### Cited Findings
**Hardware / EDA**
- KiCAD-MCP-Server discussion #112, "Agentic AI and End-to-End PCB Understanding" (posted Apr 18, 2026 by avivsabilal29; maintainer mixelpixx replied Apr 23 and Jul 6, 2026): per-net track/via/pad geometry missing — "Without this, the agent cannot compute lengths, symmetry, or proximity between nets"; no min-clearance / coupling / route-topology queries; zones and keepouts "hard to infer from DRC text"; no single graph linking schematic pins → pads → tracks → vias → zones, so "trace this signal from IC to connector" stays incomplete; stackup not surfaced; "Impedance / Zo is not a small KiCad API wrapper" (needs models/external solvers); richer data "must be paired with mechanisms" that keep LLM context and tool lists manageable because token use and "tool overload" errors grow quickly; SWIG vs IPC backends return different subsets. ### Inferences
- For the user's KiCad run, what differed from the TLDR-podcast run is predictable from #112: the loop's "design-views" phase can only reason about what the tool surface exposes as text; geometry, stackup and SI are either absent or arrive as oversized dumps, so the loop's verification step degrades to "the LLM says it looks fine" unless a script (DRC export parser, netlist diff, image render) supplies ground truth.
- A legal or physical-process artifact adds a second missing piece: there is often no cheap deterministic validator at all (no `tsc` equivalent), so the Stop-hook pattern that makes coding loops self-closing has nothing to call, and the only closure is a human gate — which the harness treats as a session boundary.
- The user's loops encode a single operator who answers questions by role; the Stanford result and the "arbitrary" conflict resolution in CLAUDE.md say that giving the same prose to several real stakeholders will not yield stable prioritisation unless priority is made explicit and mechanical (e.g. a precedence rule in code, or one owner per gate).

- No first-person write-up was found of running a Claude Code skill/plugin workflow on a hardware or legal project end-to-end and reporting what broke; evidence is tool-level (KiCad MCP) and benchmark-level (CAD, legal).
- No source was found on operations runbooks as agent processes.
- Latency of human gates (hours/days per round) is asserted here by inference from harness constraints, not measured in any opened source.

## Q8. What would stop a prose-template loop from managing other things (strongest evidence first)

### Takeaway
Ranked by strength of evidence, the blockers are: (1) prose is advisory and the vendor says so; (2) instruction density and context length measurably degrade compliance, with silent omission as the failure mode; (3) runs are non-deterministic and errors self-condition over long horizons; (4) non-text artifacts lack the validators and ground truth that make coding loops self-closing; (5) human gates are session boundaries in every harness mechanism; (6) multiple principals break prioritisation; (7) portability to other ecosystems strips the enforcement layer entirely.

### Cited Findings
1. **Prose is a request, not a guarantee (vendor statement, strongest).** "there's no *guarantee* that it'll follow your instructions. It can still decide not to do things, or do other things." "`CLAUDE.md` is for guidelines, and Claude is allowed to decide a guideline doesn't apply." Hook vs skill: "Claude interprets the instructions; outcome can vary." — [Best practices](https://code.claude.com/docs/en/best-practices); [Extend Claude Code](https://code.claude.com/docs/en/features-overview)
2. **Rule density and context length degrade compliance, silently.** 68% best-model accuracy at 500 constraints, omission-dominant, primacy-biased (IFScale); "performance grows increasingly unreliable as input length grows" across 18 models, and coherent long text is *worse* than shuffled (Chroma); Anthropic: >200 lines "reduce adherence"; skill descriptions are dropped past a 1% budget; invoked skill bodies are not re-read and are truncated after compaction. — [arXiv 2507.11538](https://arxiv.org/html/2507.11538v1); [Chroma](https://www.trychroma.com/research/context-rot); [Memory](https://code.claude.com/docs/en/memory); [Skills](https://code.claude.com/docs/en/skills)
3. **Same template, different run; and errors compound.** Single-run pass@1 varies 2.2–6.0 points, σ>1.5 at T=0, divergence within the first 1% of tokens (KTH); "non-deterministic between runs, even with identical prompts… minor changes cascade" (Anthropic); self-conditioning raises per-step error as a task lengthens and is not fixed by scale (Sinha et al.); e-discovery "trajectory collapse". Anthropic's eval tooling therefore runs each case 3× per arm and warns that one run "tells you little". — [arXiv 2602.07150](https://arxiv.org/html/2602.07150v2); [Anthropic multi-agent](https://www.anthropic.com/engineering/multi-agent-research-system); [arXiv 2509.09677](https://arxiv.org/html/2509.09677v2); [arXiv 2606.19812](https://arxiv.org/abs/2606.19812); [Plugin evals](https://code.claude.com/docs/en/plugin-evals)
4. **Other artifact types lack the closing check.** Coding loops close on `tsc`/tests/`Stop` hooks ("the single most useful line in your `CLAUDE.md` is the command that runs it"). For PCBs the agent "cannot compute lengths, symmetry, or proximity between nets" through the available tool surface and impedance "is not a small KiCad API wrapper"; CAD outputs fail executable and geometric checks that need scripted validators; legal claim-type hallucination gaps of 38–40 points are hidden by aggregate reporting (UNVERIFIED). Anthropic's remedy is scripts and machine-verifiable intermediates, not more prose. — [Best practices](https://code.claude.com/docs/en/best-practices); [KiCad MCP #112](https://github.com/mixelpixx/KiCAD-MCP-Server/discussions/112); [Skill best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)
5. **Human gates are session boundaries.** Workflows: "No mid-run user input"; subagents lose `AskUserQuestion`; hook `defer` only in `-p` mode; Stop hooks give up after 8 continuations; eval runs "never stop to ask for permission". A loop whose rounds wait on people must be split per round and cannot be end-to-end evaluated by the official harness. — [Dynamic workflows](https://code.claude.com/docs/en/workflows); [Subagents](https://code.claude.com/docs/en/sub-agents); [Hooks reference](https://code.claude.com/docs/en/hooks); [Plugin evals](https://code.claude.com/docs/en/plugin-evals)
6. **Multiple principals break prioritisation.** Frontier models "frequently fail to maintain stable prioritization under conflicting user objectives" and leak more over turns (Stanford, Apr 2026); contradictory instructions are picked "arbitrarily" (Claude Code memory docs); only harness-level managed settings/hooks impose precedence that a user cannot override. — [Stanford DEL](https://digitaleconomy.stanford.edu/publication/multi-user-large-language-model-agents/); [Memory](https://code.claude.com/docs/en/memory)
7. **Portability strips enforcement.** Hooks and agents are "Ignored" in claude.ai chat; Codex caps project docs at 32 KiB and Cursor at 500 lines with everything always-on; Gemini CLI extensions document MCP servers, context files and commands but no hooks or skills. Moving a loop out of Claude Code leaves only the prose layer, i.e. only items 1–3's failure modes with none of the mitigations. — [Platform support](https://claude.com/docs/plugins/platform-support); [Codex AGENTS.md](https://learn.chatgpt.com/docs/agent-configuration/agents-md); [Cursor rules](https://cursor.com/docs/context/rules); [Gemini CLI extensions](https://google-gemini.github.io/gemini-cli/docs/extensions)
8. **Scope and cost grow without hard caps.** Multi-agent runs use ~15× chat tokens; early systems spawned "50 subagents for simple queries"; the harness answers with numeric caps (20 concurrent subagents, 1,000 agents/run, `--max-turns`, `--max-budget-usd`) rather than prose. — [Anthropic multi-agent](https://www.anthropic.com/engineering/multi-agent-research-system); [Subagents](https://code.claude.com/docs/en/sub-agents); [Dynamic workflows](https://code.claude.com/docs/en/workflows)

### Inferences
- The consistent prescription across Anthropic's docs, the agentskills eval guide, and the EDA/CAD/legal sources is the same: shrink the prose to judgment calls at the "right altitude", push every always-true rule into a hook or deny rule, push every verification into a script that returns pass/fail, and treat each human gate as a workflow boundary. The parts of the user's loops most at risk when "managing other things" are precisely the parts that currently rely on the model remembering a convention after many turns.
- Domain transfer is gated less by the process text than by whether a deterministic validator exists for the artifact; where none exists (legal judgement, physical process), the loop degrades to LLM-judge checks with the noise characteristics documented in Q6.

### Gaps
- No controlled study was found that directly tests "same procedural template, different domain" and measures adherence drop; the ranking above combines vendor statements, constraint-following benchmarks, agentic-variance studies and domain tool reports rather than one experiment.
- Numbers for Claude-specific compliance decay under long procedural prompts (as opposed to keyword constraints) remain UNVERIFIED.
