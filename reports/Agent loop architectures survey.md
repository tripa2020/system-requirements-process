# Published agent loops all outsource "done" to something outside the model

*Research report · 2026-11-03 · for Alex · synthesised from six research notes in `research_notes/Agent loop architectures survey/` and the three loop templates (`REQUIREMENTS_LOOP.md`, `SYSTEM_DESIGN_LOOP.md`, `DESIGN_VIEWS.md`). Every claim carries its source URL and date as recorded in the notes; UNVERIFIED marks are carried through unchanged.*

Every published agent-loop architecture, from Anthropic's and OpenAI's harness posts through spec-driven platforms, code orchestration frameworks, durable workflow engines and the self-refinement literature, converges on one skeleton: durable state lives outside the model's context, the stop condition is decided by something that did not produce the work, and the human enters at the edges (goal, optional checkpoint, final approval) rather than inside every iteration. The owner's three loops already follow the first two rules and deliberately break the third: the gate is a line the owner writes in the document every pass, which makes the loop a **workflow wrapping an agent** in Anthropic's December 2024 taxonomy, with the owner as the evaluator in an evaluator-optimizer pair ([Anthropic, Dec 19 2024](https://www.anthropic.com/engineering/building-effective-agents)). What the evidence says about reproducing this across projects is specific. Anthropic's own docs now state that prompts, CLAUDE.md and skills are "non-deterministic (Claude decides)" while hooks, deny rules and managed settings are "deterministic (Claude Code enforces)" ([Claude Code best practices, current Nov 2026](https://code.claude.com/docs/en/best-practices)); instruction-following drops to roughly **68% at 500 simultaneous constraints** with silent omission as the dominant failure ([IFScale, Jul 2025](https://arxiv.org/html/2507.11538v1)); agentic runs vary **2.2 to 6.0 points pass@1 between identical runs, even at temperature 0** ([KTH, ICLR 2026](https://arxiv.org/html/2602.07150v2)); a model re-reading its own output without new information adds "near-zero" and on subjective tasks negative information ([Tao et al., Jul 31 2026, preprint](https://arxiv.org/abs/2607.28908)); and simulated users are measurably more forthcoming than real ones, inflating success by **9 to 14 points** ([Zhou et al., Mar 11 2026](https://arxiv.org/html/2603.11245v1); [Seshadri et al., Jan 28 2026](https://arxiv.org/html/2601.17087v2)). The strongest single blocker to running these loops over other artifacts is the absence of an executable oracle: code loops close on tests and type-checkers, and when nothing can return pass/fail, "'looks done' is all it has to go on" ([Claude Code best practices](https://code.claude.com/docs/en/best-practices)). No source in the notes runs a loop over a non-code document with measured outcomes, so every mapping from the published designs to the owner's loops is inference from adjacent evidence, flagged as such below.

## The question and the frame: a human-gated document loop is a workflow around an agent

The owner's loops have a fixed outer shape (0 Goal → 1 Ask by role → owner answers `round<n>.md` → 2 Morph → 3 Gate, and the six-phase design variant) with a model orchestrating tools inside each phase. Anthropic's taxonomy calls fixed code paths a *workflow* and model-directed process an *agent*, and names evaluator-optimizer as the pattern where "one LLM call generates a response while another provides evaluation and feedback in a loop," fitting "when we have clear evaluation criteria, and when iterative refinement provides measurable value" ([Anthropic, Dec 19 2024](https://www.anthropic.com/engineering/building-effective-agents)). In the owner's design the evaluator is the owner, not an LLM, which is both the loop's strength (the only verifier the evidence trusts for judgment artifacts) and its structural cost (cadence bounded by owner latency). The survey below therefore asks of each family: what is the unit of iteration, who orchestrates, where state lives, what stops the loop, and how humans enter, then what the authors and critics say breaks. Those five dimensions form the comparison table, and the final two sections rank the blockers to other domains and lay out options for reproducibility with the evidence behind each.

## Lab harness posts: files as memory, fresh contexts, and a verifier that did not write the code

**Goals.** The lab harness posts (Anthropic Nov 2025, OpenAI Feb 2026, Willison, Huntley's Ralph, Karpathy's autoresearch, and the 2026 "loop engineering" essays) all aim at the same thing: let an agent run for hours or days without a human watching, and make its output trustworthy anyway. Anthropic's problem statement is that agents "work in discrete sessions with no memory of earlier ones," that even Opus 4.5 "fell short of a production-quality app from a high-level prompt," and that the two failure patterns were trying "to do too much at once" and a later agent that "declare[d] the job done" too early ([Anthropic, Nov 26 2025](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)). OpenAI's is that "the environment was underspecified" and that when something failed "the fix was almost never 'try harder'" ([OpenAI, Feb 11 2026, archive.org copy](https://openai.com/index/harness-engineering/)).

**Loop shape.** Anthropic's unit of iteration is **one feature per fresh session**; the orchestrator is the coding agent itself, re-launched, with an initializer agent that "differ[s] only in [its] initial user prompt"; state lives in a **JSON feature list** (200+ features the model may only flip from failing to passing, chosen because the model "is less likely to inappropriately change it than Markdown"), `claude-progress.txt`, `init.sh` and git; the stop condition is every feature `passes: true` after browser-automation self-verification; the human writes the initial prompt and reviews the output ([Anthropic, Nov 26 2025](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)). OpenAI's unit is **one PR, with single runs "upwards of six hours"**; the orchestrator is Codex prompted by an engineer; state is the repo only, with a ~100-line AGENTS.md "as a map," `docs/` as "the system of record," and "execution plans with progress and decision logs that are checked into the repository"; the stop condition is "iterate in a loop until all agent reviewers are satisfied (effectively this is a Ralph Wiggum Loop)" plus CI, and humans "may review pull requests, but aren't required to," escalation being model-initiated "only when judgment is required" ([OpenAI, Feb 11 2026](https://openai.com/index/harness-engineering/)). Ralph's unit is one `PROMPT.md` run in a fresh context, "one item per loop," orchestrated by bash `while :`, with state in `PROMPT.md`, `specs/`, `fix_plan.md`, `AGENT.md` and git, no stop condition ("Eventually, Ralph will run out of things to do"), and a human who tunes the prompt "like a guitar" and decides when to `git reset --hard` ([Huntley, Jul 14 2025](https://ghuntley.com/ralph/)). Anthropic's `ralph-loop` plugin converts this into a same-session Stop hook with `--max-iterations` and an exact-match `--completion-promise` ([ralph-loop README](https://github.com/anthropics/claude-plugins-official/tree/main/plugins/ralph-loop)). Autoresearch is the purest case: the unit is one 5-minute training run, the agent edits a single `train.py`, keeps the commit if `val_bpb` improved and resets otherwise, with "LOOP FOREVER" until the human interrupts and the human's only role being to write `program.md` ([karpathy/autoresearch program.md](https://github.com/karpathy/autoresearch/blob/master/program.md)). The Claude Code docs add a strictness ladder for "done": in-prompt (the model decides), `/goal` ("a condition that a separate model checks against the conversation after every turn"), a Stop hook (exit code 2 "sends Claude back to work" until an eight-block cap), and review "By someone who didn't write the code" via `/code-review` in "a fresh subagent that never saw your conversation" ([Claude Code best practices](https://code.claude.com/docs/en/best-practices); [Claude Code /goal docs](https://code.claude.com/docs/en/goal)). The 2026 essays restate three rules: the model that wrote the work must not grade it ("way too nice grading its own homework"), no verifier means no loop ("Loops do not create signal that is not there"), and cap iterations and spend ([Osmani, Jun 7 2026](https://addyosmani.com/blog/loop-engineering/); [Mitra, Jun 21 2026](https://subhadipmitra-site.pages.dev/blog/2026/loop-engineering-verifier/); [Pulumi/Diri, Jun 9 2026](https://www.pulumi.com/blog/stop-prompting-design-the-loop/)).

**Author-stated limitations.** Anthropic calls its demo "optimized for full-stack web app development" with research and financial modelling "a future direction," and lists untested specialised agents and vision limits as open questions ([Anthropic, Nov 26 2025](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)). Its context-engineering post warns compaction "can lose subtle but critical context" and that an unguided agent "can waste context by misusing tools, chasing dead-ends" ([Anthropic, Sep 29 2025](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)). Its multi-agent research post reports early agents "spawning 50 subagents for simple queries," ~15x chat token cost, and an explicit non-fit for work that needs "all agents to share the same context" ([Anthropic, Jun 13 2025](https://www.anthropic.com/engineering/multi-agent-research-system)). OpenAI says the autonomy "should not be assumed to generalize without similar investment," that "Codex replicates patterns that already exist in the repository—even uneven or suboptimal ones," that the team "used to spend every Friday (20% of the week) cleaning up 'AI slop'" before building garbage-collection agents, and that "how architectural coherence evolves over years" is unknown ([OpenAI, Feb 11 2026](https://openai.com/index/harness-engineering/)). Huntley: "There's no way in heck would I use Ralph in an existing code base," placeholder implementations, duplicate work when ripgrep misleads it, expect "90% done" ([Huntley, Jul 14 2025](https://ghuntley.com/ralph/)). The plugin README: "Not good for: Tasks requiring human judgment or design decisions / One-shot operations / Tasks with unclear success criteria," and the completion promise "uses exact string matching" ([ralph-loop README](https://github.com/anthropics/claude-plugins-official/tree/main/plugins/ralph-loop)). Karpathy, per secondary reporting (UNVERIFIED), limits autoresearch to tasks where "quantitative evaluation is possible" ([Gigazine, Mar 24 2026](http://gigazine.net/gsc_news/en/20260324-humans-bottleneck-ai)). `/goal`'s evaluator "doesn't run commands or read files independently" ([Claude Code /goal docs](https://code.claude.com/docs/en/goal)). Willison names the real bottleneck: "how fast I can review the results" ([Willison, Oct 5 2025](https://simonwillison.net/2025/Oct/5/parallel-coding-agents/)). Note also that the current best-practices page explicitly retires 2025 advice ("manage context aggressively," "use subagents to protect your context window," "tell Claude to keep going, don't be lazy"), so citations of the 2025 posts should be read against that table ([Claude Code best practices](https://code.claude.com/docs/en/best-practices)).

**Critics.** Factor: "A loop without a reliable 'better / worse' signal isn't optimisation," Ralph "just tries more, and you pay for the difference," with a ~US$14k spend figure reported secondhand from HN ([Factor, Jan 12 2026](https://piperstreetsoftware.pages.dev/articles/ralph-loop-isnt-a-strategy.html)). xr0am: "Ralph's markdown approach requires the agent to infer these relationships from prose," fix is JSON tasks with dependency arrays ([xr0am, Jan 24 2026](https://xr0am.substack.com/p/what-ralph-wiggum-loops-are-missing)). HN on OpenAI's post (297 points): "I would never dare put that in production," "This would be much more convincing if the repos, issue trackers, etc. were accessible," and a long-run worry about a multi-MB docs folder ([HN 48416264, Jun 2026](https://news.ycombinator.com/item?id=48416264)). Böckeler's harness vocabulary splits elements into guides (feedforward) and sensors (feedback), each computational or inferential, and says "The behavioural harness (functional correctness) remains largely unsolved" even for code ([Böckeler, martinfowler.com, Apr 2 2026](https://martinfowler.com/articles/harness-engineering.html)). HumanLayer's RPI is the one lab-adjacent pattern that puts a human gate *between phases* (research and plan reviewed because "a bad line of a plan could lead to hundreds of bad lines of code"), and its author concedes it "probably isn't" right for most teams, needs "at least one person who is an expert in the codebase," and "falls flat for greenfield work" ([HumanLayer ACE-FCA](https://github.com/humanlayer/advanced-context-engineering-for-coding-agents/blob/main/ace-fca.md); [LinearB, Mar 4 2026](https://linearb.io/blog/dex-horthy-humanlayer-rpi-methodology-ralph-loop)).

**Mapping to the owner's loops.** OpenAI's "plans are first-class artifacts with progress and decision logs checked in" is the closest published analogue to the running document plus append-only changelog, and OpenAI pairs it with a doc-gardening agent the owner's loops lack. Anthropic's JSON-over-Markdown finding and xr0am's critique both argue that the parts of the running document the loop reads back as truth (gate status, round number, R-ids, which questions are open) belong in a structured file. The subagent discipline the owner already uses (per-phase agents returning condensed results, writing no files) is the part of these designs that does not depend on code at all: "returns only a condensed, distilled summary of its work (often 1,000-2,000 tokens)" ([Anthropic, Sep 29 2025](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents)).

## Spec-driven platforms record phases in markdown but enforce almost none of them

**Goals.** Kiro, Spec Kit, OpenSpec, BMAD, Tessl, Superpowers, Agent OS and cc-sdd all exist because "AI coding assistants are powerful but unpredictable when requirements live only in chat history" ([OpenSpec README](https://github.com/Fission-AI/OpenSpec)). Spec Kit's methodology states the strongest form: "Specifications don't serve code—code serves specifications" and "Debugging means fixing the spec or plan that produced bad code," while admitting "Today, practicing SDD requires assembling existing tools and maintaining discipline throughout the process" ([spec-kit spec-driven.md](https://github.com/github/spec-kit/blob/main/spec-driven.md)). Böckeler's vocabulary distinguishes spec-first (write it, let it fall out of use), spec-anchored (maintain it) and spec-as-source (humans edit only the spec) and finds "All the SDD approaches the author reviewed are spec-first, but few commit to maintaining specs over time" ([Böckeler, Oct 15 2025](https://martinfowler.com/articles/exploring-gen-ai/sdd-3-tools.html)).

**Loop shape.** Kiro's unit is a three-artifact spec (`requirements.md` in EARS form, `design.md`, `tasks.md`) in a fixed order chosen at creation, orchestrated by the IDE; state is the three markdown files plus `.kiro/steering/`; the gate is a UI act (a floating Review button and a Continue dropdown), not a document field, and Quick Spec "runs all three phases automatically without approval gates between them"; drift is handled by re-derivation ("Sync Files"), not a changelog ([Kiro: Specs](https://kiro.dev/docs/specs/); [Kiro: Feature Specs](https://kiro.dev/docs/specs/feature-specs/); [Kiro: Best Practices](https://kiro.dev/docs/specs/best-practices/)). Spec Kit's unit is a slash-command phase (`specify → clarify → plan → checklist → tasks → analyze → implement → converge`) orchestrated by whatever agent runs the generated commands; state is `memory/constitution.md` plus per-feature `spec.md`, `plan.md`, `tasks.md` on an auto-created branch; the human gate is **reviewer-owned checklist boxes** ("A reviewer marks [x] only after the requirements-quality criterion is satisfied ... implementation must not self-approve them") and `implement` "Counts checklist checkboxes and asks before proceeding if any are unchecked"; `clarify` "Asks up to five targeted questions about underspecified areas and encodes the answers back into spec.md"; `converge` is "Append-only ... its only write is adding tasks to tasks.md" ([Spec Kit agentic SDD reference](https://github.github.io/spec-kit/reference/agentic-sdd.html)). OpenSpec splits `openspec/specs/` (current truth) from `openspec/changes/<name>/` (proposals with ADDED/MODIFIED/REMOVED delta headers merged on archive into a date-prefixed archive folder); dependencies are "enablers, not gates"; "No explicit approval field or step is described," and running `/opsx:apply` is the recorded act ([OpenSpec concepts.md](https://raw.githubusercontent.com/Fission-AI/OpenSpec/main/docs/concepts.md); [OpenSpec README](https://github.com/Fission-AI/OpenSpec)). BMAD packages an agile org as named personas (Analyst Mary, PM John, PO Sofia, Architect Winston, Dev Amelia, UX Sally) and workflow skills from product brief to retrospective; gates are conversational ("you accept, partly accept, reject, or rerun each proposed revision"), with a `REPLAN` code for mid-flight changes ([BMad docs: Skills and Agents](https://docs.bmad-method.org/reference/skills-and-agents/)). Tessl's SDD tile has a `spec-before-code` rule ("implementation must never begin without an approved spec") and `.spec.md` files with inline `[@test]` links, but "does not describe a mechanism for recording" approval ([tesslio/spec-driven-development-tile](https://github.com/tesslio/spec-driven-development-tile)). Superpowers' brainstorm → plan → execute flow ends when "the user signs off on the design" and subagent-driven development "starts once the user says 'go'"; its only code-level enforcement is a session-start bootstrap hook, and "Hermes lacks a post-compaction hook, so long sessions can lose the bootstrap" ([obra/superpowers](https://github.com/obra/superpowers)). cc-sdd inverts Spec Kit: "Agents draft specs, humans approve them at phase gates, and code is what ships" ([gotalab/cc-sdd](https://github.com/gotalab/cc-sdd)).

**Author-stated limitations.** Kiro's cross-project reuse "relies on workarounds like Git submodules or package references," and spec-task execution "typically cost[s] more" than a chat credit ([Kiro: Best Practices](https://kiro.dev/docs/specs/best-practices/); [Kiro: Pricing](https://kiro.dev/pricing/)). Spec Kit's `clarify`/`checklist`/`analyze` are explicitly optional "quality gates" ([Spec Kit reference overview](https://github.github.io/spec-kit/reference/overview.html)). OpenSpec deliberately refuses blocking gates ("fluid not rigid") ([OpenSpec README](https://github.com/Fission-AI/OpenSpec)). BMAD's maintainers answered heaviness critiques with "small changes go straight to build" and v7 skills ([BMAD-METHOD README](https://github.com/bmad-code-org/BMAD-METHOD)). cc-sdd: "Beta integrations are not verified for the full autonomous loop" and per-task independent review "requires native subagents" ([gotalab/cc-sdd](https://github.com/gotalab/cc-sdd)). A Codex maintainer called manual step-gating's advantage "likely a point-in-time limitation of the models," and Codex still has no official plan/spec mode as of the thread's last comment on 2026-07-31 ([openai/codex discussion #7355](https://github.com/openai/codex/discussions/7355)).

**Critics.** Böckeler: Kiro "turned a small bug into four user stories and 16 acceptance criteria"; Spec Kit "felt like overkill for a 3–5 point feature" and agents "ignored instructions, for example by regenerating existing classes as new ones, or by over-applying constitution rules"; "Reviewing markdown is tedious"; "False sense of control" ([Böckeler, Oct 15 2025](https://martinfowler.com/articles/exploring-gen-ai/sdd-3-tools.html)). Marmelab: adding a date display "produced 8 files and about 1,300 lines of text"; a Kiro agent "marked a verification task done without any unit tests, writing manual testing instructions instead"; "spending 80% of your time reading instead of thinking"; "SDD adds little value over the plan modes and task lists coding agents already have" ([Zaninotto, Marmelab, Nov 12 2025](https://marmelab.com/blog/2025/11/12/spec-driven-development-waterfall-strikes-back.html)). Beck via Fowler: the assumption "that you won't learn anything during implementation that changes the spec" is "bizarre" ([martinfowler.com, Jan 8 2026](https://martinfowler.com/fragments/2026-01-08.html)). Thoughtworks placed SDD in Assess, warning "the field may be relearning the 'bitter lesson' that hand-crafted detailed rules for AI don't scale" ([Thoughtworks Radar, Nov 5 2025](https://www.thoughtworks.com/radar/techniques/spec-driven-development)). Frisinger: "A prose spec kept separate from the code drifts from it, and nothing signals the divergence" ([Frisinger, dev.to, year not shown](https://dev.to/tmfrisinger/spec-driven-development-is-the-prose-spec-drift-trap-reborn-4p99)). BMAD users report "230 million tokens in a week" (one user, per a Jan 2026 post), a ~2,241-line ARCHITECTURE.md to review (search snippet, UNVERIFIED), and two days yielding "Zero lines of actual code" ([asantos2000, Jan 10 2026](https://asantos2000.github.io/blog/post-3/); [guillim, Feb 8 2026](https://guillim.github.io/ai/development/2026/02/08/bmad-method-disappointment.html)). The outcome evidence points two ways: an ESEM 2026 study of **88,052 PRs across 119 repos** finds spec quality predicts neither defects (p = 0.164) nor rework (p = 0.860) and that "Specification artifacts proxy for task complexity" (search snippet; PDF not opened; a second snippet gives 100,247 PRs, UNVERIFIED which is final) ([Hill, ESEM 2026](https://drops.dagstuhl.de/entities/document/10.4230/LIPIcs.ESEM.2026.84)); a vendor-run 50-ticket benchmark finds spec workflows lift merge rate from **72% to 80–84%** on features and data pipelines but not on bug fixes, refactors or tests, with ±10pp noise and the vendor selling related services ([Uvik, run Oct 15 2026](https://uvik.net/blog/spec-driven-development-benchmark/)). The academic survey of six frameworks reports "a lack of benchmarks for the complete process" ([de Macedo, arXiv 2606.04967, Jun 3 2026](https://arxiv.org/abs/2606.04967)).

**Mapping to the owner's loops.** The critiques cluster on volume, rigidity and unverified trust, not on a recorded gate or a changelog; none of the tools writes an `Accepted on:` line into the spec, so the owner's gate-as-document-line is stricter than anything surveyed, with Spec Kit's reviewer-owned `[x]` the nearest. OpenSpec's archive of dated deltas is the published analogue of `changelog.md`; BMAD's personas and Kiro's EARS are the analogues of typed role questions and shall/should/will. Enforcement across the whole family reduces to three primitives, hooks that run before or after tool calls, counting checkboxes in a file, and read-only or append-only command scopes, which is the same list Claude Code offers.

## Orchestration frameworks make the process code and the human gate a typed value

**Goals.** LangGraph, the OpenAI Agents SDK, Microsoft Agent Framework (MAF), the Claude Agent SDK, CrewAI, Google ADK, Mastra, Pydantic AI, Vercel's eve, smolagents and DSPy differ on which layer is primary but share Anthropic's dichotomy and the advice to start simple: "If you can write a function to handle the task, do that instead of using an AI agent" ([MAF overview, ms.date 2026-10-23](https://learn.microsoft.com/en-us/agent-framework/overview/agent-framework-overview)); "regularize towards not using any agentic behaviour" ([smolagents intro](https://huggingface.co/docs/smolagents/conceptual_guides/intro_agents)); "maximize a single agent's capabilities first" ([OpenAI practical guide PDF, date not printed, widely dated Apr 2025 UNVERIFIED](https://cdn.openai.com/business-guides-and-resources/a-practical-guide-to-building-agents.pdf)). Harrison Chase's argument for low-level orchestration is that "The hard part of building reliable agentic systems is making sure the LLM has the appropriate context at each step" ([Chase, Apr 20 2025](https://www.langchain.com/blog/how-to-think-about-agent-frameworks)). Cognition argues the opposite of multi-agent: "running multiple agents in collaboration only results in fragile systems," default to "a single-threaded linear agent" ([Cognition, Jun 12 2025](https://cognition.com/blog/dont-build-multi-agents)).

**Loop shape.** In LangGraph the unit is a graph node, the orchestrator is the graph, state is a checkpointed typed object keyed by `thread_id`, and the human gate is `interrupt()` which "pauses graph execution" and "waits indefinitely until you resume" with `Command(resume=...)`; on resume "any code before the `interrupt` runs again," interrupt matching is "strictly index-based," and `MemorySaver` loses everything on restart ([LangGraph interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts); [LangGraph persistence](https://docs.langchain.com/oss/python/langgraph/durable-execution)). The OpenAI Agents SDK loop ends when the LLM "produces text output with the desired type, and there are no tool calls," caps with `max_turns`, and gates humans per tool with `needs_approval`, pausing into `RunResult.interruptions` with serializable `RunState`; approval "does not guarantee exactly-once execution" ([OpenAI Agents SDK running agents](https://openai.github.io/openai-agents-python/running_agents/); [OpenAI Agents SDK HITL](https://openai.github.io/openai-agents-python/human_in_the_loop/)). MAF models human input as typed request/response (`ctx.request_info()` / `RequestPort`), checkpoints "at the end of each superstep," saves pending requests in the checkpoint, and its Magentic orchestration tracks a progress ledger with stall counters and plan review via `approve()`/`revise(feedback)`, with the caveat "it is untested how well the Magentic orchestration will perform outside of the original Magentic-One design" ([MAF HITL, ms.date 2026-07-16](https://learn.microsoft.com/en-us/agent-framework/workflows/human-in-the-loop); [MAF checkpoints](https://learn.microsoft.com/en-us/agent-framework/workflows/checkpoints); [MAF Magentic](https://learn.microsoft.com/en-us/agent-framework/workflows/orchestrations/magentic)). The Claude Agent SDK ships Claude Code's loop ("repeats until the task is complete"), with `max_turns`, `max_budget_usd`, subagents where "only its final message returns to the parent," and human input via `canUseTool` which "can stay pending indefinitely"; `AskUserQuestion` "is not currently available in subagents"; compaction "replaces older messages with a summary, so specific instructions from early in the conversation may not be preserved" ([Agent SDK agent loop](https://code.claude.com/docs/en/agent-sdk/agent-loop); [Agent SDK user input](https://code.claude.com/docs/en/agent-sdk/user-input)). Claude Code's **dynamic workflows** move orchestration into "a JavaScript script" that "Claude writes" and a runtime executes: "A workflow moves the plan into code," with `agent()`, `pipeline()`, `parallel()`, `phase()`, JSON `schema` validation, 1,000 agents per run, deterministic replay (`Date.now()` and `Math.random()` throw), and the constraint "No mid-run user input ... For sign-off between stages, run each stage as its own workflow" ([Claude Code dynamic workflows](https://code.claude.com/docs/en/workflows)). Anthropic's stated reason is that a single context that must "both plan and execute" shows "Agentic laziness" (declaring done "after partial progress, for example addressing 35 of the 50 items"), "Self-preferential bias" ("especially when asked to verify or judge them"), and "Goal drift" ("Each summarization step is lossy") ([Claude blog, Jun 2 2026](https://claude.dev/blog/a-harness-for-every-task-dynamic-workflows-in-claude-code/)). CrewAI's `@human_feedback` with `emit` is the one primitive where "an LLM maps the free-form feedback to one of the listed outcomes" ([CrewAI flows](https://docs.crewai.com/en/concepts/flows)); its role/goal/backstory triple is asserted to "shape the agent's behavior" with no measured evidence ([CrewAI agents](https://docs.crewai.com/en/concepts/agents)). Mastra's `suspend()` snapshots "persist across deployments and application restarts" but require a declared `resumeSchema` ([Mastra suspend and resume](https://mastra.ai/docs/workflows/suspend-and-resume)). Pydantic AI's HITL is a run that *ends* with `DeferredToolRequests` and restarts with the stored conversation, "the conversation you store is everything you need to resume" ([Pydantic AI deferred tools](https://pydantic.dev/docs/ai/deferred-tools/)), and pydantic-graph warns "If you're not confident a graph-based approach is a good idea, it might be unnecessary" ([pydantic-graph](https://pydantic.dev/docs/ai/graph/graph/)). Vercel's eve keeps instructions, skills, schedules and subagents as files, parks a turn "for as long as it takes — seconds or days" on approval, replays completed steps, and defaults to `never()` approval ([eve execution model](https://eve.dev/docs/concepts/execution-model-and-durability); [eve HITL, 0.77.0 docs](https://unpkg.com/eve@0.77.0/docs/tools/human-in-the-loop.md)). DSPy is orthogonal: it compiles typed signatures against a metric, and "creative, open-ended tasks with subjective quality give the optimizer no score to maximize" (practitioner summary, UNVERIFIED) ([dspy.ai](https://dspy.ai/); [DSPy choosing an optimizer](https://raw.githubusercontent.com/stanfordnlp/dspy/main/docs/docs/diving-deeper/choosing-an-optimizer.md)).

**Author-stated limitations.** Beyond the per-framework caveats above, every durable framework warns that approval does not make the gated action exactly-once ([OpenAI Agents SDK HITL](https://openai.github.io/openai-agents-python/human_in_the_loop/); [LangGraph interrupts](https://docs.langchain.com/oss/python/langgraph/interrupts); [Mastra workflows overview](https://mastra.ai/docs/workflows/overview)). Anthropic's own docs now say that handing "the same task to a subagent doesn't make the answer any better. A fresh reviewer does help," and that a fresh subagent "can end up *slower*" because it must regather context ([Claude Code best practices](https://code.claude.com/docs/en/best-practices)). The SDK docs recommend the main conversation when "The task needs frequent back-and-forth or iterative refinement" or "Multiple phases share significant context" ([Claude Code subagents docs](https://code.claude.com/docs/en/sub-agents)).

**Critics.** HN on LangGraph: "For experienced developers, framework abstractions can add unnecessary complexity," with the LangChain defence that "nodes are just functions" and the concession "at that point, you're not using much of the framework at all" ([HN 41722243, Oct 2024](https://hn.algolia.com/api/v1/items/41722243)). A vendor-adjacent CrewAI review reports hierarchical delegation that "does not selectively delegate" (issue closed as not planned, UNVERIFIED) and four 2026 CVEs (UNVERIFIED at source) ([Atlan](https://atlan.com/know/ai-agent/what-is-crewai/)). No controlled study comparing graph-orchestrated with prose-orchestrated loops on long-horizon fidelity was found; all long-horizon claims are vendor engineering posts.

**Mapping to the owner's loops.** No framework has a primitive for "the process is a prose document the model follows"; processes are code, gates are typed values, state is a typed object or event log. The closest fits are Claude Code skills (explicitly "a template instead of a script that needs to be run verbatim"), eve's markdown instructions and schedules, and Anthropic's file-based progress artifacts ([Claude blog, Jun 2 2026](https://claude.dev/blog/a-harness-for-every-task-dynamic-workflows-in-claude-code/); [eve agent files](https://eve.dev/docs/reference/agent-files)). The consensus on gates is "gate the irreversible tool call and the plan," not "gate each phase transition"; phase gates are implemented as run boundaries, which is what the owner's loop does by stopping and waiting for `round<n>.md`. The owner's phases map to a hybrid that already exists in the owner's tool: a dynamic workflow per round, with agents prompted from the templates and results JSON-validated via `schema`, and the owner's gate at the workflow boundary.

## Durable workflow engines guarantee the outer loop and nothing about the content

**Goals.** Temporal, Inngest, Restate, DBOS, Vercel Workflow, Cloudflare Workflows, and the data orchestrators exist so a multi-step process can "retry failed steps, wait for external events, and resume across crashes and deployments" and "Pause for minutes or months, then resume from the exact point" ([Vercel Workflows, last updated Sep 4 2026](https://vercel.com/docs/workflow)). Temporal's AI pitch is "You never have to think about checkpointing" ([Temporal blog, Jul 10 2025](https://temporal.io/blog/durable-execution-meets-ai-why-temporal-is-the-perfect-foundation-for-ai)); the vendor camp argues "every failure means starting over from scratch" without it ([ZenML, Mar 1 2026](https://www.zenml.io/blog/why-agents-need-durable-execution)).

**Loop shape.** The unit is a journaled step (Temporal Activity, Inngest `step.run`, Restate `ctx.run`, DBOS step, Vercel `"use step"`, Cloudflare `step.do`); the orchestrator is a deterministic workflow function the engine re-executes against an append-only history; state is the engine-owned log of serialized step outputs; the stop condition is the function returning; and the human gate is universally "suspend until a named external message arrives," with horizons from Cloudflare's default 24-hour `waitForEvent` to Restate's "months or even years" ([Temporal workflow definition](https://docs.temporal.io/workflow-definition); [Inngest wait-for-event](https://www.inngest.com/docs/features/inngest-functions/steps-workflows/wait-for-event); [Restate durable timers](https://docs.restate.dev/develop/ts/durable-timers); [DBOS HITL](https://docs.dbos.dev/ai/hitl); [Vercel workflow concepts, last updated Sep 10 2026](https://vercel.com/docs/workflows/concepts); [Cloudflare HITL](https://developers.cloudflare.com/agents/concepts/agentic-patterns/human-in-the-loop/)). LLM non-determinism is absorbed at the step boundary: "LLM/AI invocations ... belongs in Activities" and replay returns the recorded output ([Temporal workflow definition](https://docs.temporal.io/workflow-definition)). The constraint is on the orchestrator code: Temporal's history is capped at **51,200 events or 50 MB** ([Temporal limits](https://docs.temporal.io/workflow-execution/limits)); Inngest caps runs at 30/90/366 days by plan and 1,000 steps ([Inngest usage limits](https://www.inngest.com/docs/usage-limits/inngest)); Cloudflare step values must be ≤1 MB ([Cloudflare Workers API](https://developers.cloudflare.com/workflows/build/workers-api/)). Versioning policies range from strict (Temporal patch markers; Restate "immutable, unique endpoint" per deployment, in-place edits risk journal mismatch; DBOS breaking change is "any change in what steps run or the order") through tolerant (Inngest "logs a warning rather than failing the function" on reorder, but a renamed step "can repeat a payment") to pin-and-rerun (Vercel runs "pinned to the deployment that starts them") ([Temporal Python versioning](https://docs.temporal.io/develop/python/versioning); [Restate versioning](https://docs.restate.dev/operate/versioning); [DBOS architecture](https://docs.dbos.dev/architecture); [Inngest versioning, snippet, UNVERIFIED in full](https://www.inngest.com/docs/learn/versioning); [Workflow SDK versioning](https://workflow-sdk.dev/docs/foundations/versioning)). Airflow 3.1+ added `ApprovalOperator` and an `awaiting_input` task state, and Prefect has `pause_flow_run(wait_for_input=...)` (both from snippets, UNVERIFIED), so the "cannot wait for a human" objection to DAG orchestrators is dated ([Astronomer HITL, UNVERIFIED](https://www.astronomer.io/docs/learn/airflow-human-in-the-loop)). Trigger.dev is the outlier that checkpoints the whole process image with CRIU rather than replaying ([Trigger.dev how it works](https://trigger.dev/docs/how-it-works)).

**Author-stated limitations.** Restate advises against "long-running handlers (days or months)" because old deployments must stay alive until drained ([Restate versioning](https://docs.restate.dev/operate/versioning)). Every engine requires idempotent side effects because a step "may run again" ([Inngest how functions are executed](https://www.inngest.com/docs/learn/how-functions-are-executed)). Vercel adds a governance step the engines do not provide: "Confirm that the request still matches the version they reviewed, and record the approval separately from execution" ([Vercel workflow concepts](https://vercel.com/docs/workflows/concepts)).

**Critics.** ZenML: durable execution "imposes determinism constraints that fight the inherently non-deterministic nature of LLM-based systems," and DAG orchestrators "assume you know the shape of execution before it starts" ([ZenML, Mar 12 2026](https://www.zenml.io/blog/from-pipelines-to-agents)). LittleHorse: durable-execution updates are "retry cache information, not business data" and "Versioning workflows can corrupt state of older processes" ([LittleHorse comparison](https://littlehorse.io/compare/durable-execution)). Workflow Builder: durable execution "does not solve the whole product problem" of authoring, visibility and governed iteration ([Workflow Builder, Jul 21 2026](https://www.workflowbuilder.io/blog/why-durable-execution-alone-wont-save-your-ai-agent)). The strongest counter-argument is Cidre's overnight pipeline with "no workflow engine, database, or queue": a plan file with `todo`/`done`, one markdown file per bug, commits with a `Bug: <id>` trailer, "The next run reads the same files and continues," worst case "one half-edited file in your working tree," limits being locality, sub-second step granularity, branching and "You can't show a PM a green checkmark"; add an engine "when you can name the specific durability problem it solves for you" ([Cidre, May 15 2026](https://adriacidre.com/blog/there-is-no-workflow-engine/)). In the MAF design thread, Dapr's maintainer argued "Checkpointing is expensive and unreliable compared to durable execution" because of an atomicity gap between step completion and checkpoint flush; the thread "contains no benchmarks" ([MAF discussion #1092, Oct 2025 to Feb 2026](https://github.com/microsoft/agent-framework/discussions/1092)).

**Mapping to the owner's loops.** To an engine, a prose template is a step input, not a workflow; the only hosting shape is a fixed outer loop (`for pass: step(run_llm(template, doc)); await human_gate()`) where the engine guarantees the pass counter, the timer and the gate and nothing about content. Editing the template between passes is harmless only because the engine never sees it; editing the outer loop is the breaking change every engine warns about. The engine's journal cannot be edited by hand and the gate must be a message, so a document-edit-as-gate needs a file watcher that converts a change into a signal, which reintroduces a daemon. Pass by pass: engine step = one pass's model call; journal = the running document plus git history; signal = the owner writing the gate line; timer = nothing (the markdown loop has no clock; the owner wakes it); versioning = editing the template, free in markdown, a controlled deployment in an engine. What the markdown loop lacks in engine terms is a durable timer, atomic "output written + pass marked done," and serialized access if two processes ever run the same loop; for one operator with days between passes the first is a feature, the second costs one re-run, and the third does not arise. The closest engine-side equivalents to the owner's setup are Vercel's `durable-harness` and Cloudflare's Pi harness, which persist a coding-agent *session*, not an owner-edited document ([Vercel Workflows](https://vercel.com/docs/workflow); [Cloudflare Agents, Oct 29 2026](https://developers.cloudflare.com/agents/)).

## Research and self-refinement loops gain only when new information enters

**Goals.** STORM and Co-STORM aim at pre-writing research that surfaces perspectives and "unknown unknowns"; the commercial deep-research products aim at plan → search → synthesize with citations; Self-Refine, Reflexion, evaluator-optimizer, AlphaEvolve and autoresearch aim at improving an artifact by iteration; the LLM-as-judge, debate and simulated-user literatures ask whether the model can stand in for the human evaluator.

**Loop shape.** STORM discovers N perspectives from the tables of contents of related Wikipedia articles, runs a simulated multi-turn writer–expert conversation per perspective (N and M both 5), grounds each answer in filtered web search, refines a draft outline from the conversations, and writes section by section; perspectives raised unique references from **54.36 (without) to 99.83** and editor-rated organisation from 3.25 to 4.00 (p=0.005), but verifiability was flat at 3.85 → 3.80 (p=0.843) ([Shao et al., arXiv 2402.14207, Apr 8 2024](https://arxiv.org/abs/2402.14207)). Co-STORM adds a moderator that generates questions "based on the uncited sources retrieved since the last moderator turn" and intervenes after L consecutive non-novel expert turns; "removing the moderator has a greater negative impact" than reducing to one expert, and 70% of 20 users preferred it over search ([Jiang et al., arXiv 2408.15232, 2024](https://arxiv.org/abs/2408.15232)). The deep-research products ask the user once, at plan time: OpenAI's "may ask clarifying questions to confirm your goals" and lets you "review and edit its proposed research plan" ([OpenAI Help Center](https://help.openai.com/en/articles/10500283-deep-research-in-chatgpt)); Gemini's API exposes `collaborative_planning=True` and a 60-minute cap ([Google AI Studio Deep Research docs, 2026](https://aistudio.google.com/docs/deep-research)); Perplexity's page mentions no clarifying step ([Perplexity, Feb 14 2025](https://www.perplexity.ai/hub/blog/introducing-perplexity-deep-research)). The timing evidence explains why: "Goal clarification loses nearly all its value after 10% of execution ... Deferring any clarification type past mid-trajectory performs worse than never asking," and in 300 unscripted sessions "no current frontier model asks within the empirically optimal window" ([Gulati et al., arXiv 2605.07937, May 8 2026](https://arxiv.org/abs/2605.07937)). Self-Refine (same model generates, critiques, refines, max 4 iterations) gained ~20% absolute but "Most gains (∆) are in the initial iterations" and "may not always monotonically increase" ([Madaan et al., arXiv 2303.17651, 2023](https://arxiv.org/abs/2303.17651)); Reflexion "converts binary or scalar feedback from the environment into verbal feedback," memory bounded to 1–3 reflections ([Shinn et al., arXiv 2303.11366, 2023](https://arxiv.org/abs/2303.11366)); AlphaEvolve applies to "any problem whose solution can be described as an algorithm, and automatically verified" ([DeepMind, May 14 2025](https://deepmind.google/discover/blog/alphaevolve-a-gemini-powered-coding-agent-for-designing-advanced-algorithms/)); and iteration count is now framed as optimal stopping ([Hammar et al., arXiv 2608.10729, Aug 11 2026](https://arxiv.org/abs/2608.10729)).

**Author-stated limitations.** STORM: "the quality of machine-written articles still lags behind well-revised human-authored articles, specifically in aspects of neutrality and verifiability"; the dominant residual error is "improper inferential links between different pieces of information presented in the context window," needing "high-level sensemaking rather than mere fact-level verification"; inter-annotator agreement was low (alpha 0.221–0.388) ([Shao et al. 2024](https://arxiv.org/abs/2402.14207)). OpenAI's launch post (page returned 403; quoted via Computing/Reuters, UNVERIFIED at source) says the tool "may struggle with distinguishing authoritative information from rumors" and "shows weakness in confidence calibration" ([Computing, Feb 2025](https://www.computing.co.uk/news/2025/ai/openai-announces-deep-research)). Anthropic's judge missed "SEO-optimized content farms over authoritative but less highly-ranked sources" that human testers caught ([Anthropic, Jun 13 2025](https://www.anthropic.com/engineering/multi-agent-research-system)). Self-Refine's "main limitation ... is that the base models need to have sufficient few-shot modeling or instruction-following abilities" ([Madaan et al. 2023](https://arxiv.org/abs/2303.17651)).

**Critics, and the negative results.** Intrinsic self-correction without an oracle lowers accuracy for every model tested: GPT-4 on GSM8K 95.5 → 91.5 → 89.0 over two rounds, and "the model is more likely to modify a correct answer to an incorrect one than to revise an incorrect answer to a correct one" ([Huang et al., arXiv 2310.01798, 2023](https://arxiv.org/abs/2310.01798)). Kamoi's survey finds "no prior work demonstrates successful self-correction with feedback from prompted LLMs, except for studies in tasks that are exceptionally suited," and that "the bottleneck is in the feedback generation" ([Kamoi et al., arXiv 2406.01297, 2024](https://arxiv.org/abs/2406.01297)). Tao et al. find one reflection step yields "near-zero information gain" on objective tasks and "statistically significant negative information gain" on subjective ones, that "LLMs degrade even high-quality human first-pass responses," and prescribe "External verification is necessary," exploit "Weak–strong asymmetry," and "Iteration depth should be bounded" (preprint under review, crowdworker annotators, finite-answer tasks) ([Tao et al., arXiv 2607.28908, Jul 31 2026](https://arxiv.org/abs/2607.28908)). Generator-verifier work shows GPT-4 "no better at verifying" graph colourings than solving them ([Stechly et al., arXiv 2310.12397, Oct 2023](https://arxiv.org/abs/2310.12397)). On judges: GPT-4 reaches "over 80% agreement" with humans but shows position, verbosity and self-enhancement bias ([Zheng et al., arXiv 2306.05685, 2023](https://arxiv.org/abs/2306.05685)); position-bias robustness falls below 0.5 at three or four candidates and "Most models rated their outputs more favorably, even when answer sources were anonymized" ([Ye et al., CALM, arXiv 2410.02736, Oct 2024](https://arxiv.org/abs/2410.02736)); self-preference is causally linked to self-recognition ([Panickssery et al., arXiv 2404.13076, Apr 2024](https://arxiv.org/abs/2404.13076)); and five assistants "consistently exhibit sycophancy" with humans sometimes preferring "convincingly-written sycophantic responses over correct ones" ([Sharma et al., arXiv 2310.13548](https://arxiv.org/abs/2310.13548)). On role-based review teams: debate "do[es] not reliably outperform" self-consistency and Multi-Persona "performs consistently about 7% worse" on one dataset ([Smit et al., arXiv 2311.17371, Nov 2023](https://arxiv.org/abs/2311.17371)); Degeneration-of-Thought names the failure where "Once the LLM-based agent has established confidence in its answers, it is unable to generate novel thoughts later through self-reflection," and a judge "shows a preference to the side with the same LLM as the backbone" ([Liang et al., arXiv 2305.19118, 2023](https://arxiv.org/abs/2305.19118)); across 2,410 factual questions and 162 roles "adding personas in system prompts does not improve model performance" ([Zheng, Pei et al., arXiv 2311.10054](https://arxiv.org/abs/2311.10054)); expert personas "had no significant impact on performance" and low-knowledge personas "consistently decreased performance" across six models ([Wharton, arXiv 2512.05858, Dec 5 2025](https://arxiv.org/abs/2512.05858?ref=t01.li)). The one study measuring distinct-defect coverage finds **56.5% of 154 confirmed defects were found by exactly one model**, no model exceeded ~64% recall, and "Adding a second, different-provider model raised coverage from 33.6% to 57.1%," with the author's caveat "Conclusions are directional, not a universal benchmark" ([Stone, Zenodo, Jun 3 2026](https://zenodo.org/records/20519585)). On simulated people: agents grounded in two-hour interviews reach **83–86% of a person's own test-retest consistency versus 74% for demographic prompting**, gains "asymptote once the model has observed sufficient evidence within a domain," and "the quality of individual simulation depends far less on model scale or synthetic persona engineering than on the depth and reliability of the data an agent is built from" ([Park et al., arXiv 2411.10109](https://arxiv.org/abs/2411.10109)); on τ-bench, simulated users were polite in 49.0% of turns versus 15.3% for humans, produced short turns 1.0% versus 29.0%, and lifted agent success from 63.6% with humans to up to 77.8% ([Zhou et al., arXiv 2603.11245, Mar 11 2026](https://arxiv.org/html/2603.11245v1)); swapping only the user LLM shifts success ~9 points and agents are blamed for 48.9% of simulated-user failures versus 24.5% of human-user failures ([Seshadri et al., arXiv 2601.17087, rev. Jan 28 2026](https://arxiv.org/html/2601.17087v2)).

**Mapping to the owner's loops.** STORM's perspective-guided questioning is the published analogue of typed role questions, and its measured benefit was coverage and organisation, not verifiability. The owner's morph consumes owner answers, which is the one configuration the negative results do not condemn; a morph with no new answers is exactly the self-conditioned revision that Huang, Kamoi and Tao show holds or degrades quality. The simulated owner is an LLM judge with refinement-aware, self-preference and sycophancy exposure, and the simulated-user studies predict its specific error direction: more forthcoming than the real owner, so it will over-answer from the record and therefore over-cut questions, especially where the true answer is "it depends." The role review team's "cluster by root cause" step will mostly de-duplicate correlated findings if every role shares one model; the published lever for independent findings is model-family diversity, not persona diversity.

## Packaging mechanisms: prose is a request, hooks are enforcement, and length erodes both

**Goals.** Claude Code's skills, hooks, plugins, custom subagents, CLAUDE.md and dynamic workflows, and the other ecosystems' AGENTS.md, Cursor rules, Gemini CLI extensions and MCP prompts, exist to make an agent process repeatable across sessions and projects. The docs' own trigger is explicit: "You paste the same playbook or multi-step procedure into chat for the third time → Capture it as a skill"; "A second repository needs the same setup → Package it as a plugin" ([Claude Code extend overview](https://code.claude.com/docs/en/features-overview)).

**Loop shape (what each unit packages).** A skill is a SKILL.md with `name` (≤64 chars) and `description` (≤1024 chars in the open spec; truncated at 1,536 in Claude Code's listing), three-level progressive disclosure (~100 tokens of metadata always loaded, a <5,000-token body on activation, resources on demand), "Keep your main SKILL.md under 500 lines," and in Claude Code frontmatter `allowed-tools`, `context: fork`, `hooks` ("active for the rest of the session"), `paths` and `agent` ([Agent Skills specification](https://agentskills.io/specification); [Claude Code skills](https://code.claude.com/docs/en/skills)). Invoked skill content "doesn't re-read the file on later turns," and after compaction "Claude Code can keep only the start of an invoked skill, so put the most important instructions near the top" ([Claude Code skills](https://code.claude.com/docs/en/skills)). A hook is a `command` or `http` handler on one of ~30 events; exit code 2 blocks on `PreToolUse`, `UserPromptSubmit`, `Stop`/`SubagentStop` ("Prevents stopping; continues the conversation"), `TaskCompleted` and `PreCompact`; a `PreToolUse` `deny` "blocks the tool even in `bypassPermissions` mode"; Stop hooks are capped at eight consecutive continuations without a tool call; `prompt` and `agent` hooks "ask *another model* to decide, so it isn't deterministic either" ([Claude Code hooks reference](https://code.claude.com/docs/en/hooks); [Claude Code hooks guide](https://code.claude.com/docs/en/hooks-guide); [Claude Code best practices](https://code.claude.com/docs/en/best-practices)). A custom subagent is markdown with a system prompt, a harness-enforced `tools` allowlist, `model`, `maxTurns`, `isolation: worktree`, and never `AskUserQuestion` ("always removed") ([Claude Code subagents docs](https://code.claude.com/docs/en/sub-agents)). A plugin bundles skills, agents, `hooks/hooks.json`, MCP servers and workflows "as one unit," namespaced, but plugin subagents "ignore `hooks`, `mcpServers`, and `permissionMode`," and every enabled plugin's names and descriptions sit "in Claude's context on every turn" ([Claude Code plugins](https://code.claude.com/docs/en/plugins); [Claude Code subagents docs](https://code.claude.com/docs/en/sub-agents)). CLAUDE.md is additive across the hierarchy, "target under 200 lines per CLAUDE.md file. Longer files consume more context and reduce adherence," and "if two instructions contradict each other, Claude may pick one arbitrarily" ([Claude Code memory](https://code.claude.com/docs/en/memory)). `claude plugin eval` runs each case three times with and three times without the plugin, with `regex`, `tool_used`, `tool_order`, `file_exists` graders that "cost nothing," `llm` graders that differ "more the longer the text it has to read," and runs that "never stop to ask for permission" ([Claude Code plugin evals](https://code.claude.com/docs/en/plugin-evals)). Elsewhere, AGENTS.md is prose with nearest-file-wins resolution ([agents.md](https://agents.md/)); Codex caps project docs at "32 KiB by default" ([Codex AGENTS.md guide](https://learn.chatgpt.com/docs/agent-configuration/agents-md)); Cursor rules are `.mdc` files "under 500 lines" ([Cursor rules docs](https://cursor.com/docs/context/rules)); Gemini CLI extensions bundle MCP servers, context files and TOML commands with no hooks or skills on the opened page ([Gemini CLI extensions, v0.4.0 doc](https://google-gemini.github.io/gemini-cli/docs/extensions)); hooks and agents are "Ignored" in claude.ai chat ([Plugin platform support](https://claude.com/docs/plugins/platform-support)).

**Author-stated limitations.** The hard line is Anthropic's: "there's no *guarantee* that it'll follow your instructions. It can still decide not to do things, or do other things"; "If you keep adding emphasis to a `CLAUDE.md` line and Claude still misses it, that's a sign the line belongs in a hook"; "a hook is for a rule with *zero* exceptions"; "keep the enforced set small ... If you ever find yourself at forty of them, most are probably preferences" ([Claude Code best practices](https://code.claude.com/docs/en/best-practices)). The skill-authoring guidance ranks degrees of freedom (high for prose "when multiple approaches are valid," low for "Run exactly this script" when "consistency is critical"), recommends "plan-validate-execute" with a machine-checked intermediate file, and warns Claude "might partially read files when they're referenced from other referenced files" ([Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)). The eval guide: "Fewer, better instructions often outperform exhaustive rules"; "Reasoning-based instructions ('Do X because Y tends to cause Z') work better than rigid directives" ([agentskills.io evaluating skills](https://agentskills.io/skill-creation/evaluating-skills)).

**Critics and measured limits.** IFScale: best frontier models reach only **68% accuracy at 500 instructions**, with "omission errors" dominant and a primacy bias that peaks around 150–200 instructions (single keyword task; "may not transfer") ([IFScale, arXiv 2507.11538, Jul 2025](https://arxiv.org/html/2507.11538v1)). Chroma across 18 models: "performance consistently degrades with increasing input length," "structural coherence consistently hurts" (shuffled haystacks beat coherent ones), and on ~113k-token versus ~300-token prompts "Every model scored significantly higher on focused prompts" ([Chroma, Jul 14 2025](https://www.trychroma.com/research/context-rot)). Lost-in-the-middle: recall "significantly degrades when models must access relevant information in the middle of long contexts" ([Liu et al., arXiv 2307.03172, Jul 2023](https://arxiv.org/abs/2307.03172)). KTH on 60,000 SWE-bench trajectories: "temperature 0 does not result in determinism," divergence "always happen[s] in the 1% of the total trajectory," and detecting a 2-point gain at σ=1.5% needs ~9 runs ([Bjarnason et al., arXiv 2602.07150, ICLR 2026](https://arxiv.org/html/2602.07150v2)). Self-conditioning: injecting prior errors into history gives "a sharp degradation in subsequent step accuracy," not fixed by scale, mitigated by thinking ([Sinha et al., arXiv 2509.09677, ICLR 2026](https://arxiv.org/html/2509.09677v2)).

**Mapping to the owner's loops.** The three templates total roughly 77 KB of prose; `SYSTEM_DESIGN_LOOP.md` alone is ~370 lines with a nine-category coverage map, six mandatory question types, three filters, eight agents and a fourteen-role question bank. Counted as discrete constraints, that is well into the density where IFScale predicts silent omission of the rules furthest from the top. The parts most at risk are the ones that depend on the model remembering a convention after many turns: that `Motive` and `Goal` change only by approval, that every answered question produces a logged change or a named small edit, that the simulated owner cuts only from-record questions, that nothing is written except the named files. Those are exactly the "zero exceptions" rules Anthropic says belong in hooks.

## What would stop these systems from managing other things

Ranked by strength of evidence, strongest first. "Other things" covers other domains (hardware, legal, operations), other artifact types (documents, plans, physical designs), longer horizons (weeks, years, many passes) and multiple stakeholders.

**1. No executable oracle, and the vendors say the oracle is the whole design.** Every unattended loop in the survey closes on something that returns pass/fail: tests, a type-checker, a browser screenshot, `val_bpb`, "all agent reviewers satisfied." Anthropic's current docs: "If it has nothing to run that tells it whether the work actually *is* done, 'looks done' is all it has to go on. In practice that makes you the test suite" ([Claude Code best practices](https://code.claude.com/docs/en/best-practices)). The `ralph-loop` README lists "Tasks requiring human judgment or design decisions" and "unclear success criteria" as non-fits ([ralph-loop README](https://github.com/anthropics/claude-plugins-official/tree/main/plugins/ralph-loop)); Mitra: "an LLM thinks it looks good" is "a target rather than a verifier" ([Mitra, Jun 21 2026](https://subhadipmitra-site.pages.dev/blog/2026/loop-engineering-verifier/)); AlphaEvolve is scoped to problems "automatically verified" ([DeepMind, May 14 2025](https://deepmind.google/discover/blog/alphaevolve-a-gemini-powered-coding-agent-for-designing-advanced-algorithms/)); every spec platform's "done" is a passing test or a merged PR, and Frisinger's remedy for drift ("CI keeps tests and code in sync") has no equivalent in a non-software domain ([Frisinger](https://dev.to/tmfrisinger/spec-driven-development-is-the-prose-spec-drift-trap-reborn-4p99)). For documents, policies, strategies and physical designs the only rungs left on the ladder are a separate model judging the transcript and a person approving; the loop cannot run unattended, and its cadence is Willison's review bottleneck moved from the end of the loop to every round ([Willison, Oct 5 2025](https://simonwillison.net/2025/Oct/5/parallel-coding-agents/)). The self-correction literature makes the same point from the other side: without an external signal, iteration is "neutral re-generation" or worse ([Tao et al., Jul 31 2026](https://arxiv.org/abs/2607.28908); [Huang et al. 2023](https://arxiv.org/abs/2310.01798); [Kamoi et al. 2024](https://arxiv.org/abs/2406.01297)).

**2. Prose is advisory, and rule density and context length degrade compliance silently.** Anthropic: prompts, CLAUDE.md and skills are non-deterministic and "Claude is allowed to decide a guideline doesn't apply" ([Claude Code best practices](https://code.claude.com/docs/en/best-practices)). IFScale's 68% at 500 constraints with omission dominant and primacy bias ([IFScale, Jul 2025](https://arxiv.org/html/2507.11538v1)), Chroma's monotone degradation with length and "structural coherence consistently hurts" ([Chroma, Jul 14 2025](https://www.trychroma.com/research/context-rot)), and the operational caps (200-line CLAUDE.md, 1%-of-context skill listing, invoked skills truncated after compaction) ([Claude Code memory](https://code.claude.com/docs/en/memory); [Claude Code skills](https://code.claude.com/docs/en/skills)) together predict that a long procedural template loses its later rules first and without an error. OpenAI reached the same conclusion for AGENTS.md ("Too much guidance becomes non-guidance ... It rots instantly") and moved to a ~100-line map plus mechanical linters ([OpenAI, Feb 11 2026](https://openai.com/index/harness-engineering/)). The caveat is that IFScale measures keyword constraints, not multi-step procedures; no study measures compliance decay for agentic SOPs specifically.

**3. Runs vary and errors self-condition, so longer horizons compound.** Identical runs differ by 2.2–6.0 points pass@1 even at T=0, with divergence in the first 1% of the trajectory ([KTH, ICLR 2026](https://arxiv.org/html/2602.07150v2)); "minor changes cascade into large behavioral changes" ([Anthropic, Jun 13 2025](https://www.anthropic.com/engineering/multi-agent-research-system)); per-step error rises as a task lengthens and injected prior errors sharply degrade later steps ([Sinha et al., ICLR 2026](https://arxiv.org/html/2509.09677v2)); Anthropic names laziness, self-preference and goal drift after compaction as the failure modes of single-context long runs ([Claude blog, Jun 2 2026](https://claude.dev/blog/a-harness-for-every-task-dynamic-workflows-in-claude-code/)); a legal paper calls it "trajectory collapse" where "an early misclassification silently propagates" ([arXiv 2606.19812, Jun 18 2026](https://arxiv.org/abs/2606.19812)). Anthropic's eval tooling treats one run as uninformative and runs three per arm ([Claude Code plugin evals](https://code.claude.com/docs/en/plugin-evals)). For a loop that runs many passes over weeks, a weak early round makes later rounds worse, not merely equally bad; fresh-context subagents per phase are the documented mitigation and the owner already uses them.

**4. Non-text artifacts lack the validators that make coding loops self-closing.** Through the KiCad MCP surface an agent "cannot compute lengths, symmetry, or proximity between nets," stackup is not surfaced, "Impedance / Zo is not a small KiCad API wrapper," and full DRC dumps overflow context and tool lists ([KiCAD-MCP-Server discussion #112, Apr–Jul 2026](https://github.com/mixelpixx/KiCAD-MCP-Server/discussions/112)). Text-to-CAD benchmarks report executable and geometric-validity failures (snippets only, UNVERIFIED) ([arXiv 2605.28579](https://arxiv.org/pdf/2605.28579); [arXiv 2605.07807](https://arxiv.org/html/2605.07807v1)); legal clause extraction shows 38–40-point hallucination gaps by claim type hidden by aggregates (UNVERIFIED) ([arXiv 2606.18021](https://arxiv.org/pdf/2606.18021)). Anthropic's remedy for non-text artifacts is scripts and "verifiable intermediate outputs," not more prose ([Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)). For the owner's KiCad run this predicts that the design-views and interface-probe phases can only reason about what the tool surface exposes as text; where no script supplies ground truth, verification degrades to "the LLM says it looks fine."

**5. Human gates are session boundaries in every harness mechanism, and engines cannot read a document edit as a gate.** Dynamic workflows: "No mid-run user input ... run each stage as its own workflow" ([Claude Code dynamic workflows](https://code.claude.com/docs/en/workflows)); subagents lose `AskUserQuestion` ([Claude Code subagents docs](https://code.claude.com/docs/en/sub-agents)); Stop hooks give up after eight continuations ([Claude Code hooks reference](https://code.claude.com/docs/en/hooks)); plugin evals "never stop to ask for permission" ([Claude Code plugin evals](https://code.claude.com/docs/en/plugin-evals)); every durable engine's gate is a typed message to a named wait, never an edit to the state, and no opened source describes a "state document changed" approval primitive ([Temporal message passing](https://docs.temporal.io/develop/python/message-passing); [Vercel workflow concepts](https://vercel.com/docs/workflows/concepts)). Only two published designs put a human inside the loop by construction: Huntley's optional keypress pause and HumanLayer's review of research and plan between phases ([Huntley, Jan 17 2026](https://ghuntley.com/loop/); [HumanLayer ACE-FCA](https://github.com/humanlayer/advanced-context-engineering-for-coding-agents/blob/main/ace-fca.md)). A loop whose rounds wait on people must be split per round and cannot be evaluated end-to-end by the official harness; the latency cost per round is asserted by inference, not measured in any opened source.

**6. Simulated-user fidelity collapses outside the record.** Simulated users inflate agent success by 9–14 points and are systematically more polite, more forthcoming and less ambiguous than real people ([Zhou et al., Mar 11 2026](https://arxiv.org/html/2603.11245v1); [Seshadri et al., Jan 28 2026](https://arxiv.org/html/2601.17087v2)); grounded agents reach 83–86% of a person's own consistency only "once the model has observed sufficient evidence within a domain," and demographic prompting reaches 74% ([Park et al.](https://arxiv.org/abs/2411.10109)). Managing a process whose owner's preferences are not already written down (a new domain, a new stakeholder) pushes the simulated owner into the persona regime, where it confabulates rather than abstains. No study measures LLM prediction of a specific expert's answers to open design questions.

**7. Multiple principals break prioritisation, and the harness resolves conflicts arbitrarily.** Frontier models "frequently fail to maintain stable prioritization under conflicting user objectives" and "exhibit increasing privacy violations over multi-turn interactions" (working paper; no percentages on the lab page) ([Stanford DEL, Apr 27 2026](https://digitaleconomy.stanford.edu/publication/multi-user-large-language-model-agents/)); "if two instructions contradict each other, Claude may pick one arbitrarily" ([Claude Code memory](https://code.claude.com/docs/en/memory)); only managed settings, deny rules and managed hooks impose a precedence a user cannot override ([Claude Code hooks reference](https://code.claude.com/docs/en/hooks)). Position-bias robustness falls below 0.5 at three or four candidates, so a loop ranking many stakeholders' options rather than editing one document hits judge bias directly ([Ye et al., CALM, Oct 2024](https://arxiv.org/abs/2410.02736)). The owner's loops encode one owner answering by role; giving the same prose to several real stakeholders will not yield stable prioritisation unless precedence is explicit and mechanical.

**8. Shared-context, high-dependency work does not decompose, and drift appears even with everything in place.** "Domains that require all agents to share the same context or involve many dependencies between agents are not a good fit for multi-agent systems today" ([Anthropic, Jun 13 2025](https://www.anthropic.com/engineering/multi-agent-research-system)); Cognition: "Actions carry implicit decisions, and conflicting decisions carry bad results" ([Cognition, Jun 12 2025](https://cognition.com/blog/dont-build-multi-agents)). Even with linters, docs-as-system-of-record and garbage-collection agents, OpenAI reports "Over time, this inevitably leads to drift" ([OpenAI, Feb 11 2026](https://openai.com/index/harness-engineering/)), and no published source offers a non-code drift detector for a document repeatedly morphed by the same orchestrator.

**9. Portability strips the enforcement layer, and cost scales without hard caps.** Hooks and agents are "Ignored" in claude.ai chat, Codex caps always-on project docs at 32 KiB and Cursor at 500 lines, and Gemini CLI extensions document no hooks ([Plugin platform support](https://claude.com/docs/plugins/platform-support); [Codex AGENTS.md guide](https://learn.chatgpt.com/docs/agent-configuration/agents-md); [Cursor rules docs](https://cursor.com/docs/context/rules); [Gemini CLI extensions](https://google-gemini.github.io/gemini-cli/docs/extensions)). Multi-agent runs use ~15x chat tokens and token use explains ~80% of variance ([Anthropic, Jun 13 2025](https://www.anthropic.com/engineering/multi-agent-research-system)); the harness answers with numeric caps (20 concurrent subagents, 1,000 agents per run, `--max-turns`, `--max-budget-usd`), not prose ([Claude Code subagents docs](https://code.claude.com/docs/en/sub-agents); [Claude Code dynamic workflows](https://code.claude.com/docs/en/workflows)). Applying the loop to many small operational decisions rather than a few documents inverts the value-to-cost ratio Anthropic says must justify multi-agent use.

The gaps are as important as the ranking: no primary source runs a loop over a document, policy or physical design with reported outcomes; no study tests "same procedural template, different domain" and measures adherence drop; no source quantifies the cost of a human gate per round; and the compound error of a simulated owner cutting a question the real owner never sees is unmeasured.

## What the evidence implies for reproducing the owner's loops across projects

Stated as options with the evidence behind each, not as decisions.

**Where prose suffices.** The judgment steps are the ones every source leaves to prose or to a person: picking which roles fit, ranking the 6–10 questions, deciding what forks the list, drafting proposals against the goal, clustering review findings by root cause, choosing the extra design views. Anthropic's skill guidance assigns high freedom to prose "when multiple approaches are valid" and says "Claude is already very smart. Only add context Claude doesn't already have" ([Skill authoring best practices](https://platform.claude.com/docs/en/agents-and-tools/agent-skills/best-practices)); the dynamic-workflows blog argues static scripts "need to work for all edge cases, [so] they are usually more generic" and that skill-shipped workflows should be "a template instead of a script" ([Claude blog, Jun 2 2026](https://claude.dev/blog/a-harness-for-every-task-dynamic-workflows-in-claude-code/)); the eval guide finds "Reasoning-based instructions ... work better than rigid directives" and that pass rates can improve when rules are removed ([agentskills.io evaluating skills](https://agentskills.io/skill-creation/evaluating-skills)). Option A is to keep each loop's orchestration as a SKILL.md under 500 lines with the gate and phase rules in the first screen (because invoked skills are truncated after compaction) and move the question banks, the agent prompts (Appendix A of `DESIGN_VIEWS.md` is already in verbatim-prompt form) and the kit into `references/`, `assets/` and `scripts/` ([Agent Skills specification](https://agentskills.io/specification); [Claude Code skills](https://code.claude.com/docs/en/skills)). Option B keeps the templates as they are and accepts IFScale-style omission of the later rules as the cost; the evidence that the current form works is two project runs, which the KTH variance figures say cannot distinguish a good template from a lucky run.

**Where a hook or script is needed.** The rules the templates state as absolutes are the ones the docs say belong in hooks: "Nothing else is written" (both loops), Motive and Goal change "only by approval," every system-level change gets a changelog entry, "the gate's state is the line in the doc, never the chat," subagents "write no file," and the views pages pass `check.py`. Each has a deterministic form. A `PreToolUse` hook on `Write|Edit` that denies paths outside `system_reqs/` or `system_design/` enforces the file set even in `bypassPermissions` mode ([Claude Code hooks guide](https://code.claude.com/docs/en/hooks-guide)); a `PostToolUse` hook on edits to `REQUIREMENTS.md`/`DESIGN.md` that checks `changelog.md` grew, or a `Stop` hook that exits 2 with the diff when it did not, enforces the log ([Claude Code hooks reference](https://code.claude.com/docs/en/hooks)); a `Stop` or `TaskCompleted` hook that greps for `round<n>.md` and for an `Accepted on:`/`Settled on:` line before a next-phase file may be created enforces the gate order; a custom subagent with `tools: Read, Grep, Glob` makes "writes no file" a harness limit rather than a request ([Claude Code best practices](https://code.claude.com/docs/en/best-practices)); and `check.py` already exists as the script form of the views contract. Two cautions from the same docs: a Stop hook cannot hold a turn open past eight blocks, so a gate that never clears still needs the owner or `--max-turns`, and "keep the enforced set small" because every hook "will occasionally fire when it shouldn't" ([Claude Code hooks reference](https://code.claude.com/docs/en/hooks); [Claude Code best practices](https://code.claude.com/docs/en/best-practices)). The question-quality rules (asymmetric, forks the list, one decision) can only be checked by a `prompt`/`agent` hook or `/goal`, which "isn't deterministic either." Option A ships the hooks in each skill's `hooks` frontmatter so they live for the session the loop is invoked; Option B puts them in a plugin `hooks/hooks.json` (the docs' answer to "a second repository needs the same setup"), noting plugin subagents ignore their own `hooks` so per-agent limits must be matchers in the plugin file ([Claude Code plugins](https://code.claude.com/docs/en/plugins); [Claude Code subagents docs](https://code.claude.com/docs/en/sub-agents)); Option C is Cidre's position that for one operator "the right time to add [enforcement] is when you can name the specific durability problem it solves for you," with the two KiCad and TLDR runs as the place to look for which rules were actually skipped ([Cidre, May 15 2026](https://adriacidre.com/blog/there-is-no-workflow-engine/)).

**What state to split out of the narrative document.** Anthropic chose JSON for its feature list because the model "is less likely to inappropriately change it than Markdown" and restricted edits to one field ([Anthropic, Nov 26 2025](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents)); xr0am's complaint is that prose "requires the agent to infer these relationships" ([xr0am, Jan 24 2026](https://xr0am.substack.com/p/what-ralph-wiggum-loops-are-missing)); OpenAI keeps exec-plans with progress and decision logs as first-class checked-in artifacts ([OpenAI, Feb 11 2026](https://openai.com/index/harness-engineering/)); MAF's Magentic ledgers and `DESIGN_VIEWS.md`'s own `data.js` ("the one place facts live") are the same idea. The candidates for a small structured control file are the things the loop reads back as truth and a hook could check: gate state and date, round number, the coverage map's Clear/Partial/Missing per category, open questions and their status (answered, blank-once, dropped), R-ids and their regime, one-way doors and their state, open slots and resolve-by stage. The narrative (motive, goal, requirement wording, module entries, the owner's quoted answers) stays markdown, since the owner edits it by hand and the critics' objection to SDD is markdown volume, not markdown. The changelog already satisfies the append-only property every engine journal has; what the loop lacks in engine terms is revertability per pass, which git snapshots per round would supply at no design cost ([Anthropic harness](https://www.anthropic.com/engineering/effective-harnesses-for-long-running-agents); [autoresearch program.md](https://github.com/karpathy/autoresearch/blob/master/program.md)). Option A adds one `state.json` per loop and a hook that refuses phase transitions when it disagrees with the document's gate line; Option B keeps a single source of truth in markdown and derives the structured view with a script at phase boundaries (closer to Kiro's "Sync Files" and Spec Kit's `analyze`, both read-only); Option C changes nothing and relies on the `Rounds:` and gate lines at the top of the doc, which lost-in-the-middle evidence favours as a position but which no hook currently reads.

**What the simulated-owner evidence says.** The simulated owner is in the best-supported regime (grounded in the owner's own prior words, not a persona), with Park et al.'s 83–86% ceiling when the record is deep and the 74% demographic figure as the prior when it is thin ([Park et al.](https://arxiv.org/abs/2411.10109)). The predicted error is directional: simulated users over-answer, so the filter will over-cut, most on questions whose real answer is "it depends" ([Zhou et al., Mar 11 2026](https://arxiv.org/html/2603.11245v1)); if it shares a model with the question generator it carries self-preference and refinement-aware bias, and "Avoid using the same model to generate and judge answers" is CALM's direct recommendation ([Ye et al., Oct 2024](https://arxiv.org/abs/2410.02736)); sycophancy biases it toward confirming what the record implies ([Sharma et al.](https://arxiv.org/abs/2310.13548)). Options consistent with the evidence: run the simulated owner on a different model family or at least a different `model:` in its subagent frontmatter; require the `from record:` tag to quote the exact passage (Kamoi's "decomposable" exception class, and the one thing a script can then verify by grep); keep the cut list in the round opener, as the templates already do, and sample a fraction of cut questions back to the real owner so the cut's false-positive rate is measured, which is the loop's analogue of the oracle-label baseline Huang and Kamoi say every self-correction claim needs ([Kamoi et al.](https://arxiv.org/abs/2406.01297); [Huang et al.](https://arxiv.org/abs/2310.01798)). Ask-early evidence supports the template's placement of questions before each morph rather than during it ([Gulati et al., May 8 2026](https://arxiv.org/abs/2605.07937)).

**What the role-review evidence says.** Persona prompts change tone and focus, not correctness ([Wharton, Dec 5 2025](https://arxiv.org/abs/2512.05858?ref=t01.li); [Zheng, Pei et al.](https://arxiv.org/abs/2311.10054)); STORM's roles bought coverage and organisation, not verifiability ([Shao et al. 2024](https://arxiv.org/abs/2402.14207)); same-model reviewers reading the same anchored draft degenerate ([Liang et al. 2023](https://arxiv.org/abs/2305.19118)); distinct defects come from different model families, with a second family raising coverage from 33.6% to 57.1% ([Stone, Jun 3 2026](https://zenodo.org/records/20519585)); `/code-review`'s design, "a fresh subagent that never saw your conversation," is the harness-level version of the same rule ([Claude Code best practices](https://code.claude.com/docs/en/best-practices)); and "A reviewer that's asked to find problems will always find *something*" warns against fixing every finding ([Claude Code best practices](https://code.claude.com/docs/en/best-practices)). The design review team already reads cold "without the conversation," on Opus, one role each; the options the evidence adds are to spread roles across model families (the subagent `model:` field supports `sonnet`/`opus`/`haiku`/`fable`), to have the clustering step report overlap between roles so convergence is visible, and to keep the at-most-eight cluster cap as a guard against reviewer over-finding. Co-STORM's ablation suggests the highest-value addition to a question round is a moderator injecting directions no role raised, which the CTO-and-future-sight agent partly plays ([Jiang et al. 2024](https://arxiv.org/abs/2408.15232)).

**When to morph and how many passes.** Every loop with durable gains has new external input per iteration; most of the gain arrives in the first iteration and curves turn non-monotone after ([Madaan et al. 2023](https://arxiv.org/abs/2303.17651); [Huang et al. 2023](https://arxiv.org/abs/2310.01798); [Tao et al. 2026](https://arxiv.org/abs/2607.28908)). The templates already tie Morph to owner answers and the exit test to "every answered question produced a logged change"; the evidence supports treating a round with no new answers as a round to skip, and the pass count as a stopping problem tied to measured change (no accepted edits from the last answers) rather than a constant ([Hammar et al., Aug 2026](https://arxiv.org/abs/2608.10729)). STORM's dominant residual error, unsupported inferential links formed during synthesis, says the owner's gate read should look for new connections the morph introduced, not only check that each answer was applied ([Shao et al. 2024, Appendix E](https://arxiv.org/abs/2402.14207)).

**How to know the loop reproduced.** Whether `round<n>.md` exists, `changelog.md` was appended, the gate line flipped only after the validator ran, and the subagents never wrote files are exactly what `file_exists`, `regex`, `tool_used` and `tool_order` graders check for free; whether the round asked good questions needs an `llm` grader that is noisy on long text; a human-gated loop cannot run end-to-end under `claude plugin eval` because runs never pause, so each phase would be its own eval case fed a fixed prior-state fixture ([Claude Code plugin evals](https://code.claude.com/docs/en/plugin-evals)). Three runs per arm is the floor and ~9 runs are needed to see a 2-point change ([KTH, ICLR 2026](https://arxiv.org/html/2602.07150v2)). Dynamic workflows offer a middle path for the agent-heavy phases (the views builders, the review team, the fact and interface probes): a saved workflow per phase with JSON `schema` on each agent's return, resumable and replayable, with the owner's gate at the workflow boundary, which is the form Anthropic itself recommends for sign-off between stages ([Claude Code dynamic workflows](https://code.claude.com/docs/en/workflows)). `DESIGN_VIEWS.md`'s "Next step, undecided" (a `/design-views <project> <pass>` skill) is the same move for the one loop that is already closest to script form.

## Conclusion

The survey changes the framing of the owner's problem from "which published architecture should these loops copy" to "which published failure each part of these loops is already exposed to." The published designs are unanimous that a loop is only as good as its verifier, and the owner's loops already have the strongest verifier available for judgment artifacts, the owner writing a line in the document; what they lack is not a better loop but the three things every unattended design added after its first failures: a structured control file the model may only flip, a deterministic check that fires whether or not the model remembers the rule, and a measured baseline (how often the simulated owner cuts wrongly, how much the role reviewers overlap, how many passes change anything) against which the next template edit can be judged. Each of those can be added without turning prose into code, and the evidence on instruction density says the prose should get shorter, not longer, as they are added.

The second shift is in what "reproducible across projects" can mean. The engines, frameworks and spec platforms all treat the human gate as a run boundary, and the harness evidence says a Stop hook can hold a session open only eight blocks; so reproducibility for these loops is per phase, not per loop: a skill plus hooks that make one pass behave the same way on the next project, with the owner's latency between passes as the designed cadence rather than a defect. Where the loops will stop transferring is predictable from the ranking above: the moment an artifact has no script that can return pass/fail (a PCB's impedance, a legal judgment, a second stakeholder's priority), the loop falls back to LLM-judge checks with the noise and bias documented here, and the only published remedy is to build the validator or keep the human.
